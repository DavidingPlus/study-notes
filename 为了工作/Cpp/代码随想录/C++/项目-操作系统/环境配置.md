# 软件包安装、实验代码获取

在准备好ubuntu后，需要配置一些环境，参考[官方文档](https://pdos.csail.mit.edu/6.S081/2020/tools.html)，主要是在命令行中执行三个命令：

```shell
sudo apt-get install git build-essential gdb-multiarch qemu-system-misc gcc-riscv64-linux-gnu binutils-riscv64-linux-gnu 
sudo apt-get remove qemu-system-misc
sudo apt-get install qemu-system-misc=1:4.2-3ubuntu6
```

```
第一条命令为开发和调试RISC-V架构的程序准备必要的工具和环境，第二和第三条命令卸载旧版的软件包，并安装指定版本的qemu虚拟化工具的misc系统仿真部分（如果不是ubuntu20.04版本，可能第三条命令会报错：Version '1:4.2-3ubuntu6' for 'qemu-system-misc' was not found  ，如文章开头所说）
```

下一步是获取项目的实验代码仓库，我们就是要在这个仓库上做改进。先进入工作目录，然后将实验代码克隆到本地：

```shell
git clone git://g.csail.mit.edu/xv6-labs-2020
```

这个仓库的代码实现了一个类似于Unix但是简单的多的xv6操作系统，但是他有很多常用的功能没有实现。我们的实验就是运用操作系统的知识，完善各种功能。

# Git

大家可以看到左边的目录中，我们一共要做11个实验，这对应了这个仓库中的11个git分支：

![1733119734243-ef7a3f21-d4d5-4c5c-a9c7-baf1ef4e2dac.jpeg](./img/5LBCOcTsJ7NEzLWi/1733119734243-ef7a3f21-d4d5-4c5c-a9c7-baf1ef4e2dac-564783.jpeg)

所以这个实验中还需要学一些git的基础操作，参考[这篇文章](http://xv6.dgs.zone/labs/use_git/git1.html)

使用git来管理一个项目有很多好处：

```
-  git会跟踪项目的每次更改，你可以查看历史版本，可以回滚到之前的任意版本  
-  你可以在不同分支中同时处理多个功能或修复问题，然后将更改合并到主分支，保持项目的稳定性和条理性  
-  可以在每次提交中记录改动信息，明确说明谁在什么时候做了什么改动  
-  可以并行开发，分别在不同分支上工作，减少冲突  
- ......
```

未来如果想要从事互联网相关工作，应该也是要接触到git的。所以此时从这个项目出发，学习一些git的基础操作也是一举两得。当然git的使用也不是这个项目的重点，如果大家在使用git的时候遇到什么问题，请优先尝试自行解决（自学能力是十分重要的），如果实在无法解决，可以在讨论区描述遇到的问题，大家一起分享解决方案，一起学习

在这个项目中，我对git的使用有两个建议：

1. 如果是和我一样使用VSCode的同学，建议安装`Git Graph`插件：

![1732937562290-01f562a2-dd30-48a3-8a77-9c085c0604e3.png](./img/5LBCOcTsJ7NEzLWi/1732937562290-01f562a2-dd30-48a3-8a77-9c085c0604e3-188339.png)

这是一个可以将仓库状态可视化的插件，对于每个提交节点都可以美观的展示出来，效果如下：

![1732937863998-8ce07c3f-274c-4e46-9e65-8b526a4d4568.jpeg](./img/5LBCOcTsJ7NEzLWi/1732937863998-8ce07c3f-274c-4e46-9e65-8b526a4d4568-901591.jpeg)这样就可以很清晰的看到这个仓库每个阶段的状态、每次提交做了什么改动、都有哪些分支等信息，可以很简单的切换到任一个节点时刻的代码

2.每个实验都由不同数量的小实验组成，建议是每个小实验都建立一个测试分支，当完成这个小实验后，再合并到这个实验分支上，可视化效果如下：

![1732966946541-aef39283-44c9-4ad6-a074-7ed7df165963.jpeg](./img/5LBCOcTsJ7NEzLWi/1732966946541-aef39283-44c9-4ad6-a074-7ed7df165963-890867.jpeg)
