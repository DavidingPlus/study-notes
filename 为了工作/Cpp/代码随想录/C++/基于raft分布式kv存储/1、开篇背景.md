# 1、开篇背景

**项目背景：**

在当今大规模分布式系统的背景下，需要可靠、高可用性的分布式数据存储系统。

传统的集中式数据库在面对大规模数据和高并发访问时可能面临单点故障和性能瓶颈的问题。

为了解决这些问题，本项目致力于构建一种基于Raft一致性算法的分布式键值存储数据库，以确保数据的一致性、可用性和分区容错性。

**学习此项目的目的是：**

学习Raft算法之后动手实现，一个基于此算法核心的k-v存储的分布式数据库。

当然分布式不仅仅只是解决了单点故障的问题，若单服务器突然因为某种情况断电或者库房起火，使用分布式可以保证数据备份的完善关键数据不会丢失。

**可以收获：**

+ **Raft一致性**：选主、日志复制与提交，保障线性一致
+ **高可用容错**：多数派存活，故障/分区可自愈
+ **KV引擎**：跳表索引 + 状态机应用，支持数据恢复
+ **RPC通信**：Protobuf 自定义协议，超时/重试/心跳
+ **读写策略**：强一致读 / ReadIndex / 租约读，幂等与重试
+ **性能并发**：复制批量化、线程池与定时任务优化
+ **工程化**：统一异常、链路日志（traceId）、监控告警

最后附上本项目github位置：[https://github.com/youngyangyang04/KVstorageBaseRaft-cpp](https://github.com/youngyangyang04/KVstorageBaseRaft-cpp)

**注：**<font style="color:rgb(47, 48, 52);">需要注意的是，分布式式的共识算法实现本身是一个比较严谨的过程，因为其本身的存在是为了多个服务器之间通过共识算法达成一致性的状态，从而避免单个节点不可用而导致整个集群不可用，因此在学习过程中必须要考虑不同情况下节点宕机、断网情况下的影响。</font>

<font style="color:rgb(47, 48, 52);">许多情况需要仔细思考并实验以验证算法正确性，其中的思考别人无法代替，本项目的内容</font>**<font style="color:rgb(47, 48, 52);">只能作为分布式共识算法Raft的一个入门的实现，方便大家快速理解Raft算法</font>**<font style="color:rgb(47, 48, 52);">，从而写到简历上，如果想全部理解分布式算法的精髓只能多思考多看多总结。</font>
