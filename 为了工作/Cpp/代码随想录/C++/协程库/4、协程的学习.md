# 4、协程的学习

## <font style="color:#333333;">协程的基础知识</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">学习协程需要记住两个关键英文单词：</font>

* **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">resume</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：恢复</font>
* **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">yield</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：暂停</font>

### 什么是协程？

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">协程也被称为</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">轻量级线程、用户态线程</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">简单理解：协程是一种执行过程中可以 </font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">yield（暂停）</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 和 </font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">resume（恢复）</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 的子程序。也可以说，</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">协程就是函数 + 函数运行状态的组合</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">怎么理解？</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">普通函数一旦开始执行，就会一直运行到结束，中间不会中断，更不会执行到一半跑去执行别的函数。</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">但协程不同：我们会先为协程绑定一个入口函数，并且可以在函数执行的</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">任意位置暂停</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">，转而去执行其他函数，之后再回到暂停点继续执行。</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">因此说协程是函数与其运行状态的结合 —— 协程会绑定入口函数，并完整记录函数的运行状态。</font>

### <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">协程如何实现暂停与恢复？</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">核心在于</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">协程上下文</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">当协程执行 yield 暂停时，上下文会记录当前暂停的位置；当执行 resume 恢复时，就从这个位置继续运行。</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">协程上下文包含了函数当前状态下</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">全部 CPU 寄存器的值</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">，这些寄存器记录了函数的栈帧、指令执行位置等信息。</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">把这些寄存器内容恢复给 CPU，就能实现从暂停处继续执行。</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">需要注意：</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">单线程下，协程的 resume 和 yield 一定是同步配对的</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">一个协程执行 yield 暂停，必然对应另一个协程执行 resume 恢复，因为线程不能没有执行主体。</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">此外，协程的 yield 和 resume 完全由</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">应用程序自身控制</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">，这一点和线程不同。</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">线程的创建、运行与调度由操作系统内核管理；而协程的运行与切换由用户态程序控制，因此协程也被称为</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">用户态线程</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。</font>

### 对称协程与非对称协程

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">对称协程和非对称协程是协程的一种分类方式，它们的区别主要在于协程的切换方式和控制流的管理。</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">对称协程</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">对称协程允许协程之间直接相互调用和切换，控制流（只有拿到执行权的协程才可以执行）可以在多个协程之间自由转移。在这种协程模型中，协程之间地位平等，可以相互切换，类似于函数调用。每个协程可以</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">显式</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">决定将控制权转移到</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">哪个</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">协程。</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">特点：</font>

* <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">自由切换：协程可以显式地将控制权转移到其他协程。</font>
* <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">平等地位：所有协程在调度时</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">没有</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">层级关系，彼此平等。</font>
* <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">复杂性：因为可以任意切换协程，可能会让程序逻辑变得复杂。</font>

```plain
//因为还没有学习云风的库先用python模拟
def coroutine_a():
print("A1")
switch_to(coroutine_b)
print("A2")

def coroutine_b():
print("B1")
switch_to(coroutine_a)
print("B2")

coroutine_a();
//运行逻辑
先打印A1，然后yield暂停a函数协程跳转到b函数执行打印B1，然后resume恢复a函数打印A2，最后打印B2(因为每个协程相当于调度器一样执行过去完了不就回来了。)
```

**非对称协程**

非对称协程会出现类似堆栈的调用方与被调用方关系，也就是形成了层级结构。具体来说：A 调用了 B，B 作为被调用方，在执行 yield 时会把控制权交还给调用它的 A，而不是其他协程。

（这里使用了原文档的图）

![1730706736055-3bb93a3d-2da4-46b0-90af-342098e1e99e.png](https://cdn.davidingplus.cn/images/2026/09/11/1730706736055-3bb93a3d-2da4-46b0-90af-342098e1e99e-748571.png)

举个例子：程序运行时，由协程调度器先调用函数 a 执行；a 在执行过程中调用 b，b 又调用 c。当 c 执行 yield 时，返回的不是调度器或其他协程，而是它的调用方 b；b 执行 yield 则返回给 a；a 再返回给协程调度器。从中可以看出：谁通过 resume 切换到另一个协程，那么对方 yield 时就一定会返回到谁。

**使用场景：**

**对称协程：**

* <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">复杂多任务协作：多个任务或子任务需要频繁、直接地相互交互，共同协同完成一个目标。</font>
* <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">状态机驱动系统：多个状态需要彼此直接切换，减少中间调度步骤。</font>
* <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">需要频繁切换的计算密集型任务：适合高性能场景，例如游戏开发，一个任务可以主动切换到另一个。</font>

**非对称协程：**

* <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">IO 密集型应用：需要等待大量 IO 事件完成，例如 Web 服务器的请求处理、数据库读写。</font>
* <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">任务调度：在多线程或任务调度框架中，协程由中心调度器统一调度，例如 Web 框架中的请求 / 响应循环。</font>
* <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">简单的生产者 - 消费者模型：例如异步事件循环中，非对称协程的启动、暂停、恢复都由调度者统一控制，结构清晰，避免协程之间复杂的相互依赖。</font>

\*\*小总结： \*\*

对称协程更灵活，非对称协程更简单。对称协程不仅需要绑定入口函数运行，还要显式指定下一个要切换的协程，相当于每个协程都承担了部分调度器的工作。这种设计实现麻烦，程序也更难管理和维护。而非对称协程可以依靠专门的调度器统一负责调度，每个协程只需要执行自己的入口函数，执行结束或 yield 时把运行权交回调度器，再由调度器选择下一个要执行的协程即可。

### <font style="color:rgb(51, 51, 51);">有栈协程与无栈协程</font>

**有栈协程：**

用独立的执行栈来保存协程的上下文信息（当前状态全部寄存器的值）。当协程被yield挂起时，有栈协程会保存当前的执行状态(例如函数调用栈，局部变量、传递的参数等)，<font style="color:rgb(51, 51, 51);">并将控制权交还给调度器。当协程被恢复时，栈协程会将之前保存的执行状态恢复，从上次挂起的地方继续执行。类似于内核态线程的实现，不同协程间切换还是要切换对应的栈上下文，只是不用陷入内核而已。</font>

**<font style="color:rgb(51, 51, 51);">无栈协程：</font>**

<font style="color:rgb(51, 51, 51);">它不需要独立的执行栈来保存协程的上下文信息，协程的上下文都放到公共内存中，当协程被挂起时，无栈协程会将协程的状态保存在堆上的数据结构中，并将控制权交还给调度器。当协程被恢复时，无栈协程会将之前保存的状态从堆中取出，并从上次挂起的地方继续执行。</font><font style="color:rgb(51, 51, 51);">协程切换时，使用状态机来切换，就不用切换对应的上下文了，因为都在堆里的。</font><font style="color:rgb(51, 51, 51);">比有栈协程都要轻量许多。</font>

**补充总结：有栈和无栈的区分是看能不能任意的保存并切换嵌套函数，因为无栈不切换调用栈，所以无法做到嵌套多个函数还能像有栈一样切换。**

### 独立栈与共享栈

独立栈和共享栈都是\*\*<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">有栈协程</font>\*\*（支持嵌套函数调用与切换）。

共享栈的本质是：所有协程运行时\*\*<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">共用同一块栈空间</font>\*\*。每次协程切换时，需要将当前使用的栈内容拷贝出来保存。对协程调用 yield 时，该协程的栈内容会被暂存；需要多少内存就开辟多少，减少内存浪费。当 resume 恢复该协程时，之前保存的栈内容会被重新拷贝回运行时栈。

**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">独立栈</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">独立栈指每个协程都拥有</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">独立、固定大小</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">的栈空间。优点：协程切换时</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">不需要拷贝内存</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">，切换更快。缺点：会造成</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">内存浪费</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。因为栈在运行时不能随意扩容，否则会导致栈上指针失效；为了避免溢出，每个协程必须预先分配足够大的栈。而多数协程实际用不了这么大空间，因此会造成内存浪费与开辟大内存带来的性能损耗。</font>

**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">优缺点：</font>**

* <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">独立栈：实现简单，但</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">耗内存、易冗余、可能溢出</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。</font>
* <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">共享栈：使用公共大栈空间，</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">更安全、更省内存</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">；但协程频繁切换需要频繁拷贝内存，</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">更耗 CPU</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。</font>

### 协程的优缺点

#### 优点：

**1、高效资源利用**

1. **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">效利用资源</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">轻量级：协程比线程更轻量。线程的创建与上下文切换开销较大，而协程在用户态管理，复用线程资源，开销极小。</font>
2. **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">简化异步编程</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">可读性高：协程让异步代码可以用</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">同步风格编写</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">，大幅提升可读性与可维护性。</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">例如 Python 中的 </font><code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">async/await</font></code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">，就能让异步逻辑看起来像同步代码。</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">补充：</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">同步：执行流程确定、按序完成，调用后一定能得到结果。</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">异步：事件触发时机不可预测，执行流程不阻塞、不等待。</font>

3. **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">非阻塞执行</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">提升性能：协程支持非阻塞操作，在等待 I/O 等耗时操作时，可以切换执行其他任务，提高并发能力与响应速度。</font>
4. **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">适合高并发场景</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">协程开销小，适合处理大量并发任务，例如高并发网络请求、I/O 密集型服务。</font>

***

#### <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">缺点</font>

1. **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">调试更困难</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">协程涉及异步与延迟执行，出现问题时跟踪调用栈比同步代码更复杂，尤其多个协程相互切换时。</font>
2. **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">管理复杂度更高</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">协程调度、优先级等高级特性需要专门的调度器或框架支持，会增加系统复杂度。</font>
3. **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">状态管理更复杂</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">协程之间共享与管理状态容易引入竞争，需要谨慎设计，避免数据不一致问题。</font>
4. **<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">无法直接利用多核资源（最重要）</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">线程是操作系统调度的基本单位。</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">单线程内的多个协程始终是串行执行</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">的，只能使用一个 CPU 核心。因此协程通常需要配合</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">多线程 / 多进程</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">才能充分利用多核。</font>

#### <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">如何理解？</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">现代系统中，线程由操作系统直接调度，系统可以把不同线程分配到不同 CPU 核心上并行执行。</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">而</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">单线程只能被分配到一个 CPU 核心</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">，即使内部有很多协程，也必须等一个协程 yield 之后，另一个协程才能 resume 执行。</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">应用程序只能</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">逻辑上</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">控制协程的创建、暂停、恢复、切换，但</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">无法决定线程跑在哪个 CPU 核心</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">—— 这是操作系统的权限。协程完全依附于线程、由应用程序管理，因此</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">能否使用多核，取决于线程数量</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。单线程 + 多协程，</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">永远无法利用多核</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。</font>

### <font style="color:rgb(51, 51, 51);">协程类的实现</font>

<font style="color:rgb(51, 51, 51);">在正式编写协程类之前，⾸先需要学习⼀下Linux下的ucontext族函数，ucontext机制是GNU C库提供的⼀组创 建，保存，切换⽤户态执⾏上下⽂的API，这是协程能够随时切换和恢复的关键。</font>

**<font style="color:rgb(51, 51, 51);">项目里主要会用到的API如下：</font>**

```cpp
// 上下⽂结构体定义
// 这个结构体是平台相关的，因为不同平台的寄存器不⼀样
// 下⾯列出的是所有平台都⾄少会包含的4个成员
typedef struct ucontext_t {
 // 当前上下⽂结束后，下⼀个激活的上下⽂对象的指针，只在当前上下⽂是由makecontext创建时有效
struct ucontext_t *uc_link;
 // 当前上下⽂的信号屏蔽掩码
sigset_t          uc_sigmask;
 // 当前上下⽂使⽤的栈内存空间，只在当前上下⽂是由makecontext创建时有效
stack_t           uc_stack;
 // 平台相关的上下⽂具体内容，包含寄存器的值
mcontext_t        uc_mcontext;
    ...
 } ucontext_t;
 // 获取当前的上下⽂
int getcontext(ucontext_t *ucp);
 // 恢复ucp指向的上下⽂，这个函数不会返回，⽽是会跳转到ucp上下⽂对应的函数中执⾏，相当于变相调⽤了函数
int setcontext(const ucontext_t *ucp);
 // 修改由getcontext获取到的上下⽂指针ucp，将其与⼀个函数func进⾏绑定，⽀持指定func运⾏时的参数，
// 在调⽤makecontext之前，必须⼿动给ucp分配⼀段内存空间，存储在ucp->uc_stack中，这段内存空间将作为
func函数运⾏时的栈空间，
// 同时也可以指定ucp->uc_link，表示函数运⾏结束后恢复uc_link指向的上下⽂，
// 如果不赋值uc_link，那func函数结束时必须调⽤setcontext或swapcontext以重新指定⼀个有效的上下⽂，
否则程序就跑⻜了
// makecontext执⾏完后，ucp就与函数func绑定了，调⽤setcontext或swapcontext激活ucp时，func就会被
运⾏
void makecontext(ucontext_t *ucp, void (*func)(), int argc, ...);

// 恢复ucp指向的上下⽂，同时将当前的上下⽂存储到oucp中，
// 和setcontext⼀样，swapcontext也不会返回，⽽是会跳转到ucp上下⽂对应的函数中执⾏，相当于调⽤了函数
// swapcontext是sylar⾮对称协程实现的关键，线程主协程和⼦协程⽤这个接⼝进⾏上下⽂切换
int swapcontext(ucontext_t *oucp, const ucontext_t *ucp);
```

更详细的介绍和示例可以参考：[ucontext-人人都可以实现的简单协程库-阿里云开发者社区 (aliyun.com)](https://developer.aliyun.com/article/52886)

<font style="color:rgb(51, 51, 51);">sylar的协程实现使⽤了⾮对称模型，且保证⼦协程不能再创建新的协程，即协程不能嵌套调⽤，⼦协程只能与线程主协程进⾏切换，这种模型简单，⾮常容易理解。</font>

那么问题来了那么神奇的ucontext到底是什么？

**3、ucontext组件是什么？**

<code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">ucontext_t</font></code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 是 </font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">POSIX 标准</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">中定义的一个结构体，用于表示</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">用户态上下文</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">，通常用于实现</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">非对称协程</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">的上下文切换。</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">在 </font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">System V 系列系统</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">（如 Linux）中，头文件 </font><code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"><ucontext.h></font></code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 定义了两个结构体：</font>

* <code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">mcontext_t</font></code>
* <code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">ucontext_t</font></code>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">同时提供了四个核心函数：</font>

* <code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">getcontext()</font></code>
* <code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">setcontext()</font></code>
* <code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">makecontext()</font></code>
* <code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">swapcontext()</font></code>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">利用这些结构体和函数，可以在</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">单个进程内实现用户级线程切换（即协程）</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">其中：</font>

* <code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">mcontext_t</font></code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 类型与</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">机器架构相关</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">，对用户不透明（底层硬件相关上下文）。</font>
* <code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">ucontext_t</font></code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 结构体则至少包含以下字段：</font>

```cpp
         typedef struct ucontext {
               struct ucontext *uc_link;//系统恢复时指向的上下文
               sigset_t         uc_sigmask;
               stack_t          uc_stack;
               mcontext_t       uc_mcontext;
               ...
           } ucontext_t
```

**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">ucontext 组件（续）</font>**

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">如果当前上下文是由 </font><code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">makecontext()</font></code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 创建的上下文，那么当它运行终止时，系统会自动恢复 </font><code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">uc_link</font></code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 指向的上下文。</font>

* <code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">uc_sigmask</font></code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：该上下文中</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">阻塞的信号集合</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。</font>
* <code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">uc_stack</font></code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：该上下文所使用的</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">栈空间</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。</font>
* <code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">uc_mcontext</font></code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">：保存该上下文的</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">机器相关状态</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">，包括寄存器、调用线程现场等。</font>

**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">补充：uc\_mcontext 的作用</font>**

<code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">uc_mcontext</font></code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 保存了处理器的特定状态，包括各种寄存器值和其他硬件相关信息。当一个上下文被</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">保存</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">时，寄存器的值与处理器状态会被存入 </font><code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">uc_mcontext</font></code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">；当上下文被</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">恢复</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">时，</font><code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">uc_mcontext</font></code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 中的内容会被重新加载回处理器寄存器，使 CPU 回到保存时的状态。</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">简单理解：</font>

<code>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">uc_mcontext</font>**</code>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 是实现协程上下文保存与恢复的关键。</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">它通过保存 </font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">PC 指针（指令位置）</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 和 </font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">栈指针（调用栈）</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">，实现协程的挂起与恢复。</font>

小总结：

当一个子程序（如协程）被暂停时，系统会将当前处理器状态保存到 <code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">uc_mcontext</font></code> 中，包括所有寄存器值与必要的硬件状态，保证未来可以完整恢复。当需要恢复执行时，系统再把 <code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">uc_mcontext</font></code> 中的状态加载回 CPU 寄存器，从而恢复上下文、继续执行。

**<font style="color:rgb(51, 51, 51);">讲了那么多来练习一下吧</font>**

<font style="color:rgb(51, 51, 51);">先复习一下那四个函数的用途：\ </font><font style="color:rgb(51, 51, 51);">getcontext：初始化ucp结构体，将当前上下文保存到ucp中</font>

```cpp
int getcontext(ucontext_t *ucp);
```

<font style="color:rgb(51, 51, 51);">setcontext:</font>

<font style="color:rgb(51, 51, 51);">设置当前的上下文为ucp，setcontext的上下文应该通过getcontext或者makecontext取得，如果调用成功则不返回。如果上下文是通过getcontext()取得，程序会继续执行这个调用后面的内容比如我们刚刚的helloworld，如果上下文是通过调用makecontext取得,程序会调用makecontext函数的第二个参数指向的函数，如果func函数返回,则恢复makecontext第一个参数指向的上下文第一个参数指向的上下文context\_t中指向的uc\_link.如果uc\_link为NULL,则线程退出。</font>

```cpp
int setcontext(const ucontext_t *ucp);
```

<font style="color:rgb(51, 51, 51);">makecontext:</font>

<font style="color:rgb(51, 51, 51);">makecontext修改通过getcontext取得的上下文ucp(这意味着makecontext前必须调用getcontext)。然后给上下文指定一个栈空间ucp->stack,设置后继的ucp->uc\_link.</font>

<font style="color:rgb(51, 51, 51);">当上下文通过setcontext或者swapcontext激活后，执行func函数，argc为func的参数个数，后面是func的参数序列。当func执行返回后，继承的上下文被激活，如果继承上下文ucp->link为NULL时，线程退出。</font>

```cpp
void makecontext(ucontext_t *ucp, void (*func)(), int argc, ...);
```

<font style="color:rgb(51, 51, 51);">swapcontext:</font>

<font style="color:rgb(51, 51, 51);">保存当前上下文到 oucp 中，然后激活 upc 上下文。</font>

<font style="color:rgb(51, 51, 51);">如果执行成功，getcontext返回0，setcontext和swapcontext不返回；如果执行失败，getcontext,setcontext,swapcontext返回-1，并设置对于的</font><font style="color:rgb(51, 51, 51);">error</font><font style="color:rgb(51, 51, 51);">.</font>

```cpp
int swapcontext(ucontext_t *oucp, ucontext_t *ucp);
```

**正式开始：**

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">虽然我们称协程是</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">用户态的轻量级线程</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">，但实际上多个协程</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">同属于一个线程</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">任意时刻，同一个线程内</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">不可能同时运行两个协程</font>**<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">。</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">我们可以把协程调度简化理解为：主函数调用协程 1，运行协程 1 直到它切回 / 返回主函数；主函数再调用协程 2，运行协程 2 直到它切回 / 返回主函数。</font>

**<font style="color:rgb(51, 51, 51);">示意步骤如下,这也是非对称协程的运行过程：</font>**

**实现用户级线程(协程)的过程是：**\ <font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">我们首先调用 </font><code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">getcontext()</font></code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 获取当前上下文。</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">修改获取到的 </font><code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">ucontext_t</font></code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 结构体，用于配置新的上下文：例如指定栈空间及其大小、设置用户线程执行完毕后返回的后继上下文（即主函数上下文）等。</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">调用 </font><code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">makecontext()</font></code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 创建上下文，并指定用户线程需要执行的函数。</font><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">切换到该用户线程上下文并执行（如果将后继上下文设置为主函数，那么用户线程执行完毕后会自动返回到主函数）。</font>

<font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">下面的 </font><code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);">context_test</font></code><font style="color:rgb(0, 0, 0);background-color:rgba(0, 0, 0, 0);"> 函数实现了上述逻辑。</font>

```cpp
#include<ucontext.h>
#include<stdio.h>
void func1(void *arg)
{
    puts("1");
    puts("11");
    puts("111");
    puts("1111");
}//此函数用来给makecontext使用
void context_test()
{
    char stack[1024*128];//设置栈的空间
    ucontext_t child,main;//设置两个上下文
    getcontext(&child);//将此时的上下文信息保存到child中
    child.uc_stack.ss_sp=stack;//指定栈空间
    child.uc_stack.ss_size=sizeof(stack);//指定栈空间大小
    child.uc_stack.ss_flags=0;
    child.uc_link=&main;//设置后继上下文
    makecontext(&child,(void(*)(void))func1,0);//修改上下文让其指向func1的函数
    swapcontext(&main,&child);//切换到child上下文，保存当前上下文到main
    puts("main")//如果设置了后继上下文也就是uc_link指向了其他ucontext_t的结构体对象则makecontext中的函数function
                //执行完成后会返回此处打印main，如果指向的为nullptr就直接结束
}
int main()
{
    context_test();
    return 0;
}
```

**具体的分析：**\ <font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">	首先我们设计一个 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">func1</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 函数，供 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">makecontext</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 使用。当 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">makecontext</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 执行后，会将 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">child</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 上下文绑定到 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">func1</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 函数，只有通过 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">swapcontext</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 等函数切换后，</font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">func1</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 才会真正执行。</font>

<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">可以看到，</font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">getcontext</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 和 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">makecontext</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 是</font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">成对使用</font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">的，必须在 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">makecontext</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 之前</font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">正确设置好 </font>**<code>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">ucontext_t</font>**</code>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 结构体</font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">。</font><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">调用 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">swapcontext</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 后，会将当前上下文保存到 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">main</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">，并切换到 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">child</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 上下文执行。</font><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">由于 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">child</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 已经通过 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">makecontext</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 绑定了 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">func1</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">，因此程序会执行 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">func1</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 并打印结果。</font><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">又因为 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">uc_link</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 设置了后继上下文，所以 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">func1</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 执行完毕后，会从 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">swapcontext</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 的下一行继续执行，打印 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">main</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">，至此整个流程结束。</font>

<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">所以，通过这套流程：</font>

**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">非对称协程的特点得以体现</font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">。</font>

<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">协程 1 是 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">child</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">，主协程是 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">main</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">。控制权从主协程（</font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">context_test</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 中的 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">main</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 上下文）切换到 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">child</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">（协程 1），执行完成后，控制权再回到 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">main</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 继续执行。</font>

<code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">swapcontext</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> + </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">uc_link</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 共同实现了协程的</font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">切换与恢复</font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">，完成了</font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">main → child → main</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 的完整协程流转。</font>

### <font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">引出一个小问题：</font>

<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">如果在 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">getcontext</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 之后，有一段循环打印 </font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">“Hello World”</font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 的代码，会不会因为 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">makecontext</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 初始化上下文，导致这段代码</font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">无法执行</font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">？</font>

<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">答案：</font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">会，肯定无法执行。</font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">原因：</font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">makecontext</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 会</font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">修改上下文</font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">，让上下文在通过 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">setcontext</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> / </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">swapcontext</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 激活时，</font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">直接跳转到绑定的函数执行</font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">。函数执行完毕后，会根据 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">uc_link</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 回到后继上下文，也就是 </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">swapcontext</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> / </font><code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">setcontext</font></code><font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 的下一句继续执行，</font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">不会回到 </font>**<code>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">getcontext</font>**</code>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 之后、</font>**<code>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">makecontext</font>**</code>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);"> 之前的代码</font>**<font style="color:rgb(28, 31, 35);background-color:rgba(0, 0, 0, 0);">。</font>

```cpp
#include <stdio.h>
#include <ucontext.h>

void func1() {
    puts("In func1");
}

int main() {
    ucontext_t context;
    getcontext(&context);
    context.uc_stack.ss_sp = malloc(8192);
    context.uc_stack.ss_size = 8192;
    context.uc_link = NULL;
    makecontext(&context, func1, 0);
    setcontext(&context);
    puts("This will not be printed");
    puts("Hello World");
    return 0;
}
```
