# 04-文件下载功能

## 业务需求

对于网盘系统而言，需要实现文件下载功能，除了普通的文件下载功能以外，还需要考虑以下如下的特性：

1. 文件上传采用分片上传的形式，文件内容是以片的进行存储的，如何下载的时候变成一个完整的文件？
2. 不仅可以下载单个文件，还要支持多个文件，或者文件夹下载，比如：同时勾选多个文件下载、勾选多个文件夹下载等。

除了以上功能要求以外，还需要考虑到系统的可用性：

1. 避免超大文件下载导致系统内存溢出问题

## 实现思路

![1772053907872-6e99ecb5-780e-48cf-8808-2dc470c7c7b9.png](https://cdn.davidingplus.cn/images/2026/09/11/1772053907872-6e99ecb5-780e-48cf-8808-2dc470c7c7b9-411138.png)

网盘采用**压缩下载**的方案，在服务器端把文件按照对应的分块合并成独立的文件，再把这些独立的文件压缩成一个完整的压缩包，客户下载压缩包后解压则会保留完整的目录结构和文件内容。在文件夹过大时会提示内容过多，重新选择下载。

如果在客户端进行文件的合并，能够减轻服务器压力，但是开发内容较多，需要进行前后端的交互导致内存压力大，造成服务器假死。

1. 在服务器本地生成一个临时目录专门存放合并的文件和生成的压缩包，为了达到不互相干扰，通过创建userid 目录和 downloadname 目录去隔离。
2. 第二步：文件合并，根据文件Id获取完整的文件信息，并且做判断
   1. 如果是文件，再根据文件md5获取切块记录集合，并且按顺序输出到临时目录，自动合并成完整的文件
   2. 如果是文件夹，先在临时目录下创建对应文件夹，并且递归查询其下面的子文件/文件夹，然后做处理
3. 第三步：压缩文件（夹）
4. 第四步：把压缩包的下载路径拼接好并返回给客户端。

### 文件压缩读写

#### **<font style="color:rgb(51, 51, 51);">FileInputStream 直接读写</font>**

```java
@Test
public void compressWithFileInputStream() {
    //1. 压缩文件
    File zipFile = new File("/home/data/test.zip");
    //2.包装成ZipOutputStream输出流
    ZipOutputStream zipOut = new ZipOutputStream(new FileOutputStream(zipFile));    
    File[] files=new File("/home/data/fragmentFiles").listFiles();
    for (File f:files) {
        InputStream input = new FileInputStream(f);
        // 创建压缩的Enrty
        zipOut.putNextEntry(new ZipEntry(f.getName()));
        // 文件流直接写入
        byte[] bytes=new byte[input.available()];
        input.read(bytes);
        zipOut.write(bytes);
        input.close();
    }
    zipOut.close();
}
```

#### **<font style="color:rgb(51, 51, 51);">BufferedInputStream 带缓存方式</font>**

```java
@Test
public void compressWithBufferedInputStream() {

    File zipFile = new File("/home/data/test.zip");
    //2.包装成ZipOutputStream输出流

    BufferedOutputStream bout = new BufferedOutputStream(zipOut);
```

#### **<font style="color:rgb(51, 51, 51);">NIO读取和写出文件</font>**

```java
@Test
public void compressWithNio() {
    //1. 压缩文件
    File zipFile = new File("/home/data/test.zip");
    //2.包装成ZipOutputStream输出流
    ZipOutputStream zipOut = new ZipOutputStream(new FileOutputStream(zipFile));    
    // 创建通道
    WritableByteChannel wchannel = Channels.newChannel(zipOut);               
    File[] files=new File("/home/data/fragmentFiles").listFiles();
    for (File f:files) {
        //输入流通道
        FileChannel fc = new FileInputStream(f).getChannel();
        zipOut.putNextEntry(new ZipEntry(f.getName()));       
        //往目标通道写数据
        fc.transferTo(0, fc.size(), wchannel);
  }
}
```

## 代码实现

**目前已实现**：

1. 用户私有空间单文件下载。
2. 用户私有空间单文件预览。
3. 分享页单文件下载（带提取码校验与过期校验）。
4. 后端流式输出，前端 Blob 保存/展示。

### 3.1 个人下载

#### 3.1.1 接口入口

`GET /api/v1/files/file/download`\
`networkdisk-business/networkdisk-files/src/main/java/com/disk/files/controller/UserFileController.java:209`

控制器做三件事：

1. 解密 `fileId`。
2. 注入 `HttpServletResponse`。
3. 注入当前登录用户 ID（`UserIdUtil.get()`）并下发到服务层。

#### 3.1.2 服务器主流程

核心方法：\
`networkdisk-business/networkdisk-files/src/main/java/com/disk/files/domain/service/impl/UserFileServiceImpl.java:293`

执行顺序：

1. 根据 `fileId` 获取 `user_file` 记录。
2. 校验归属权限（必须是当前用户）\
   `UserFileServiceImpl.java:726`
3. 校验不能下载文件夹\
   `UserFileServiceImpl.java:741`
4. 进入 `doDownload` 组装响应并输出文件流\
   `UserFileServiceImpl.java:759`

#### 3.1.3 响应头与流式输出

1. 统一设置 CORS 与 Content-Type\
   `UserFileServiceImpl.java:775`
2. 设置下载文件名与 `Content-Disposition`\
   `UserFileServiceImpl.java:789`
3. 设置 `Content-Length`（来自 `file.file_size`）。
4. 委托存储引擎把真实文件写入响应输出流\
   `UserFileServiceImpl.java:805`

#### 3.1.4 存储引擎层

统一接口：

* `StorageEngine.realFile(ReadFileContext)`\
  `networkdisk-common/networkdisk-file/src/main/java/com/disk/file/core/StorageEngine.java:54`

读取上下文：

* `ReadFileContext`（`realPath + outputStream`）\
  `networkdisk-common/networkdisk-file/src/main/java/com/disk/file/context/ReadFileContext.java:16`

本地引擎实现：

* `LocalStorageEngine#doReadFile`\
  `networkdisk-common/networkdisk-file/src/main/java/com/disk/file/local/LocalStorageEngine.java:101`

底层输出：

* `FileUtil.writeFileToOutputStream(...)` 使用 `FileChannel.transferTo`\
  `networkdisk-common/networkdisk-base/src/main/java/com/disk/base/utils/FileUtil.java:215`

### 3.2 预览功能

#### 3.2.1 接口入口

* `GET /api/v1/files/file/preview`\
  `networkdisk-business/networkdisk-files/src/main/java/com/disk/files/controller/UserFileController.java:222`

#### 3.2.2 服务层流程

核心方法：\
`networkdisk-business/networkdisk-files/src/main/java/com/disk/files/domain/service/impl/UserFileServiceImpl.java:311`

流程与下载类似，但关键差异是：

1. 不设置附件下载头。
2. 预览 Content-Type 优先使用 `file.file_preview_content_type`，无值回落 `application/octet-stream`。\
   `UserFileServiceImpl.java:826`
3. 同样通过 `realFile2OutputStream` 流式写出。\
   `UserFileServiceImpl.java:805`

### 3.3 分享下载

#### 3.3.1 接口入口

* `GET /api/v1/shares/share/file/download`\
  `networkdisk-business/networkdisk-share/src/main/java/com/disk/share/controller/UserShareController.java:97`

#### 3.3.2 服务层流程

核心方法：\
`networkdisk-business/networkdisk-share/src/main/java/com/disk/share/domain/service/impl/ShareServiceImpl.java:180`

执行顺序：

1. 校验分享是否存在、是否过期。
2. 私密分享校验提取码。
3. 校验 `share_file` 映射存在。
4. 校验 `user_file` 和 `file` 未被删除且真实文件存在。
5. 设置响应头后，`InputStream.transferTo(outputStream)` 流式下载。\
   `ShareServiceImpl.java:212`
