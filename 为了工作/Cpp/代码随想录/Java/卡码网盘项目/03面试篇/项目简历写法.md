# 项目简历写法

## 简历项目写法

这个项目涉及的技术和知识点非常多，面试官有很多可以深挖的点，制作简历时可以选择自己掌握的方面进行着重描述，避免面试官问到不熟悉的实现细节。

### 详细版

```markdown
项目名称：卡码网盘 / 分布式网盘系统（NetworkDisk）
项目时间：20XX.XX - 20XX.XX
项目角色：后端开发 / 全栈开发（按实际填写）

项目描述：
基于 Spring Boot 3 + Spring Cloud Alibaba + Dubbo 构建的网盘系统，围绕用户认证、文件上传下载、目录管理、文件搜索、分享、回收站和 AI 文档能力构建完整业务闭环。项目采用 auth、gateway、files、user、share、recycle、ai 等模块拆分，前端基于 Vue3 实现文件管理、分享访问和 AI 问答交互。

技术栈：
Java 21、Spring Boot 3.2.2、Spring Cloud Alibaba、Spring Cloud Gateway、MyBatis-Plus、MySQL、Redis、Redisson、Dubbo、Nacos、Elasticsearch、Canal、PostgreSQL/pgvector、Vue3、Vite、Pinia、Element Plus、Apache Tika。

主要职责：
1. 参与文件模块核心能力开发，完成单文件上传、分片上传、断点续传、秒传校验、分片合并、文件预览、流式下载、目录树、重命名、复制、移动等功能实现。
2. 参与认证与鉴权链路实现，打通登录、用户信息获取、根目录初始化和业务侧登录校验流程，基于 JWT + Redis + AOP 方式完成用户上下文提取与接口鉴权。
3. 参与文件搜索能力建设，落地“ES 索引优先 + MySQL 回退”的文件名搜索方案，并通过 Canal 实现 `user_file -> ES` 增量同步。
4. 参与分享模块开发，完成公开/私密分享、提取码校验、匿名访问、分享文件下载，以及基于 Redisson 延迟队列的分享到期自动清理。
5. 参与回收站模块开发，基于 `user_file.deleted` 实现回收站列表、批量还原、批量彻底删除，并对已删除目录执行子节点递归展开处理。
6. 参与 AI 能力接入，支持文档摘要、标签生成、单文件问答，落地 pgvector 检索增强问答方案，并在无检索结果时回退全文解析。

项目成果：
1. 形成“上传、管理、搜索、分享、回收站、AI”一体化网盘闭环，覆盖常见网盘核心场景。
2. 文件下载采用流式输出，避免大文件整块加载带来的内存压力，提升下载链路稳定性。
3. 搜索链路支持 ES 检索与数据库回退，保证索引未命中或未同步完成时仍可正常搜索。
4. 分享模块支持公开/私密访问与过期自动清理，降低无效链接长期残留带来的安全风险。
5. AI 模块支持单文件摘要、标签和问答，并通过向量检索提升文档问答的上下文命中效果。

技术难点：
1. 文件上传链路同时覆盖单文件上传、秒传和分片合并，兼顾大文件稳定性与重复文件上传效率。
2. 下载与预览链路基于文件流转发实现，避免大文件读取对 JVM 内存造成冲击。
3. 搜索服务采用“搜索词拆分 + ES 优先查询 + MySQL 回退 + 服务端统一高亮”方案，兼顾体验与可用性。
4. 分享模块通过 Redisson `RDelayedQueue` 在事务提交后登记过期删除任务，保证分享到期后自动逻辑清理。
5. AI 文档问答支持 pgvector 相似片段召回，在检索不可用或命中不足时回退 Tika 全文解析，保证功能可用性。
6. 采用模块化拆分方式组织 auth/gateway/files/user/share/recycle/ai 服务，具备 Dubbo RPC、网关转发和多服务联调经验。
```

## 项目亮点提炼

1. 微服务边界清晰：当前仓库按 `auth / gateway / files / user / share / recycle / ai` 拆分，职责分工明确。
2. 文件能力完整：覆盖目录树、重命名、复制、移动、删除、回收站、预览、下载、上传、分片合并、秒传。
3. 搜索链路可讲清：文件名搜索采用 ES 优先、MySQL 回退、服务端高亮、Canal 增量同步。
4. 分享链路有细节：支持公开/私密分享、提取码校验、匿名访问、文件下载、到期自动清理。
5. AI 能力有差异化：支持单文件摘要、标签、问答，具备 pgvector 检索增强与全文回退逻辑。
6. 鉴权方案有工程性：认证服务结合 Sa-Token，业务接口侧采用 JWT + Redis + AOP 完成登录态校验和用户上下文注入。
7. 前后端联动完整：前端 Vue3 文件页、分享页、回收站页、AI 抽屉与后端接口链路可整体说明。
8. 可扩展性较好：搜索、分享、AI、回收站都保留了较明确的边界，便于继续迭代。

## 面试可讲的模块

下面是面试时可以提前准备的问题，回答可以参考[常见面试题-项目相关](https://www.yuque.com/chengxuyuancarl/edybxb/ev75k6ugs6nael2i)

### 1. 文件上传下载

* 单文件上传、分片上传、分片合并、秒传校验如何协同工作。
* 为什么下载和预览都采用流式输出。
* 目录树、复制/移动时如何避免非法目标目录。

### 2. 搜索

* 搜索为什么不是只查 MySQL。
* ES 索引结构如何设计，为什么只索引文件名而不是全文内容。
* Canal 如何把 `user_file` 的增量变更同步到 ES。
* 为什么 ES 没结果时还要回退 MySQL。

### 3. 分享

* 分享记录和分享文件映射为什么拆成 `share`、`share_file` 两张表。
* 私密分享如何做提取码校验。
* 为什么过期删除采用 Redisson 延迟队列而不是定时扫库。
* 分享下载时为什么要重新回查 `user_file` 和 `file`。

### 4. 回收站

* 为什么回收站不单独建表，而是直接基于 `user_file.deleted`。
* 还原和彻底删除时，为什么要对已删除目录做 BFS 展开。
* 当前彻底删除为什么只删 `user_file`，没有直接删物理文件。

### 5. AI 文档能力

* 文档摘要、标签和单文件问答分别如何落地。
* 单文件问答为什么先走 pgvector 检索，再回退全文解析。
* Tika 在文档解析中的作用是什么。
* 为什么向量检索和业务文件记录要按 `userId + userFileId` 做隔离。

## STAR 法则示例

### STAR-1：文件搜索可用性优化

* S：网盘文件数量增加后，仅依赖数据库做文件名模糊查询，检索体验和扩展性都有限。
* T：实现更可扩展的搜索链路，并保证索引未命中时搜索功能仍可用。
* A：设计 `user_file_index` ES 索引，接入 Canal 同步 `user_file` 增量数据；服务层实现搜索词拆分、ES 优先查询、MySQL 回退和服务端高亮。
* R：搜索结果支持高亮展示，并在 ES 未命中或未同步完成时继续通过数据库回退保证可用性。

### STAR-2：分享链接安全与过期治理

* S：文件分享需要同时满足公开访问、私密提取码和过期自动失效等要求。
* T：实现分享创建、匿名访问、提取码校验和过期清理完整链路。
* A：设计 `share` 与 `share_file` 结构，落地公开/私密分享接口；下载前校验分享状态、提取码和文件映射；通过 Redisson 延迟队列在事务提交后登记过期删除任务。
* R：分享链路具备基础安全控制能力，并可在到期后自动逻辑清理无效分享记录。

### STAR-3：AI 文档问答能力建设

* S：普通文件管理能力只能完成上传下载，无法支持围绕文档内容进行快速理解与问答。
* T：为文件页增加 AI 摘要、标签和单文件问答能力。
* A：接入 AI 模块，基于 Tika 解析文档正文；构建 pgvector 文档分片索引；单文件问答时先检索相关分片作为上下文，在检索不可用或命中不足时回退全文解析。
* R：实现面向单文件的摘要、标签和问答能力，提升文档理解效率，并保证在向量检索异常时仍可继续回答。

### STAR-4：文件误删恢复机制

* S：文件删除后直接不可恢复，用户误删风险高。
* T：实现“逻辑删除 -> 回收站 -> 还原/彻底删除”的回收站闭环。
* A：基于 `user_file.deleted` 设计回收站列表和操作接口；还原与彻底删除前按当前用户已删除记录做 BFS 展开，保证删除目录时相关已删除子节点能被一并处理。
* R：删除操作具备可恢复能力，降低用户误删带来的数据风险，同时支持批量彻底清理。
