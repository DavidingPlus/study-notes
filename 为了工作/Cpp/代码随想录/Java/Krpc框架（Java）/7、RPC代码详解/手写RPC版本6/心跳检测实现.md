大家先来看一看一位录友之前提出的issue![1741337355028-003c0d9f-2eac-4d0d-a7c6-ccb46c5db456.png](https://cdn.davidingplus.cn/images/2026/09/11/1741337355028-003c0d9f-2eac-4d0d-a7c6-ccb46c5db456-078892.png)

客户端在请求结束后 **就直接关闭eventLoop** 其实并不是一个合理的操作

如以下情况

![画板](https://cdn.davidingplus.cn/images/2026/09/11/1741344249541-181a58f1-9181-487a-97f1-3680572ef0a6-799712.jpeg)

如果Client在处理一次请求后就关闭eventLoop，

那么接下来的请求都将无法处理

但是 我们又需要及时维护C-S间的连接，避免Client和Server端出现大量连接资源占用的浪费

这种情况，我们可以引入Netty 的心跳检测 来实现 动态维护连接资源

### 什么是心跳检测
心跳检测是用于保障服务端与客户端之间通信连接状态的实时监控。客户端不断向服务端发送心跳包（心跳包就是一组数据，自行定义，能够进行区分就好）。服务端在一定时间范围内能够正常接收客户端心跳包的话，就认为连接正常活跃；如果服务端在一定时间内没有接收到客户端心跳包的话，就认为连接出现中断或异常，那么就可以进行连接断开、释放资源等操作，从而保证节省服务端连接资源。



### 前置学习
实现心跳检测，将通过由Netty提供的以下类：



1、IdleStateHandler



主要有三个关键参数，通过构造函数传入：



+ 读空闲时间，readerIdleTime/readerIdleTimeSeconds
+ 写空闲时间，writerIdleTime/writerIdleTimeSeconds
+ 读写空闲时间，allIdleTime/allIdleTimeSeconds



如果对某一个参数不感兴趣，只需要将对应参数设置为0即可



2、触发事件



当通道有一段时间没有执行读取、写入或同时执行这两种操作时，触发IdleStateEvent。



+ 没有读取操作，将触发 IdleState.READER_IDLE事件
+ 没有写入操作，将触发IdleState.WRITER_IDLE事件
+ 没有读写事件，将触发IdleState.ALL_IDLE事件



3、处理事件



当触发上诉事件时，我们需要接收并且进行对应处理，通过重写handler中的userEventTriggered方法，进行事件处理，参考如下:

```java
public class MyHandler extends ChannelDuplexHandler {
      @Override
      public void userEventTriggered(ChannelHandlerContext ctx, Object evt) throws Exception {
          if (evt instanceof IdleStateEvent) {
              IdleStateEvent e = (IdleStateEvent) evt;
              if (e.state() == IdleState.READER_IDLE) {
                  ctx.close();
              } else if (e.state() == IdleState.WRITER_IDLE) {
                  ctx.writeAndFlush(new PingMessage());
              }
          }
      }
  }
```

## 2.Handler实现和添加
### 服务端Handler
<font style="color:#000000;">服务端关注读空闲事件和写空闲事件，也就是如果服务端在10秒内没有收到</font>[<font style="color:#000000;">客户端</font>](https://so.csdn.net/so/search?q=%E5%AE%A2%E6%88%B7%E7%AB%AF&spm=1001.2101.3001.7020)<font style="color:#000000;">的心跳包，或者20秒内没有发送数据，将会关闭与客户端之间的连接。</font>

krpc-core项目下com.kama.server.netty下

**<font style="color:#000000;">1.新增HeartbeatHandler类</font>******

<font style="color:#000000;">用于处理IdleStateEvent事件，服务端关注读空闲事件和写事件，当触发事件时，将会关闭与客户端之间的连接</font>

```java
@Slf4j
public class HeartbeatHandler extends ChannelDuplexHandler {

    @Override
    public void userEventTriggered(ChannelHandlerContext ctx, Object evt) throws Exception {
        try {
            // 处理IdleState.READER_IDLE时间
            if(evt instanceof IdleStateEvent) {
                IdleStateEvent idleStateEvent = (IdleStateEvent) evt;

                IdleState idleState = ((IdleStateEvent) evt).state();
                // 如果是触发的是读空闲时间，说明已经超过n秒没有收到客户端心跳包
                if(idleState == IdleState.READER_IDLE) {
                    log.info("超过10秒没有收到客户端心跳， channel: " + ctx.channel());
                    // 关闭channel，避免造成更多资源占用
                    ctx.close();
                }else if(idleState ==IdleState.WRITER_IDLE){
                    log.info("超过20s没有写数据,channel: " + ctx.channel());
                    // 关闭channel，避免造成更多资源占用
                    ctx.close();
                }
            }}catch (Exception e){
            log.error("处理事件发生异常"+e);
        }
    }
}
```

**2.****<font style="color:rgb(77, 77, 77);">NettyServerInitializer添加组件</font>**

<font style="color:rgb(77, 77, 77);">IdleStateHandler 触发事件</font>

<font style="color:rgb(77, 77, 77);">HeartbeatHandler 处理事件</font>

### 客户端Handler
<font style="color:#000000;">客户端只关注写空闲事件，如果在8秒内没有任何写操作，将会触发写空闲事件，向服务端发送心跳包。</font>

krpc-core项目下com.kama.client.netty下

**<font style="color:#000000;">1.新增HeartbeatHandler类</font>**

```java
@Slf4j
public class HeartbeatHandler extends ChannelDuplexHandler {

    @Override
    public void userEventTriggered(ChannelHandlerContext ctx, Object evt) throws Exception {
        if(evt instanceof IdleStateEvent) {
            IdleStateEvent idleStateEvent = (IdleStateEvent) evt;

            IdleState idleState = idleStateEvent.state();

            if(idleState == IdleState.WRITER_IDLE) {
                ctx.writeAndFlush(RpcRequest.heartBeat());
                log.info("超过8秒没有写数据，发送心跳包");
            }
        }else {
            super.userEventTriggered(ctx, evt);
        }
    }
}
```

**2.****<font style="color:rgb(77, 77, 77);">NettyClientInitializer添加组件</font>**

```java
@Slf4j
public class NettyClientInitializer extends ChannelInitializer<SocketChannel> {
    public NettyClientInitializer(){}
    @Override
    protected void initChannel(SocketChannel ch) throws Exception {
        ChannelPipeline pipeline = ch.pipeline();
        // 使用自定义的编码器和解码器
        try {
            // 根据传入的序列化器类型初始化编码器
            pipeline.addLast(new MyEncoder(Serializer.getSerializerByCode(3)));
            pipeline.addLast(new MyDecoder());
            pipeline.addLast(new NettyClientHandler());
            pipeline.addLast(new MDCChannelHandler());
            // 客户端只关注写事件，如果超过8秒没有发送数据，则发送心跳包
            pipeline.addLast(new IdleStateHandler(0, 8, 0, TimeUnit.SECONDS));
            pipeline.addLast(new HeartbeatHandler());
            log.info("Netty client pipeline initialized with serializer type: {}",Serializer.getSerializerByCode(3).getType());
        } catch (Exception e) {
            log.error("Error initializing Netty client pipeline", e);
            throw e;  // 重新抛出异常，确保管道初始化失败时处理正确
        }
    }
}
```



## 3.定义心跳消息类型 和处理逻辑
实现上述操作后，会发现 Client和Server中只有Client 方的<font style="color:#000000;">HeartbeatHandler类中有发送心跳包的操作。</font>

```java
ctx.writeAndFlush(RpcRequest.heartBeat());
```

<font style="color:#000000;">为什么不能直接发送字符串或者默认码来表示心跳？</font>

<font style="color:#000000;">因为Client已经定义了RpcRequest作为消息发送类型。如果直接发送字符串等，就会导致编解码和读取出现异常</font>



既然如此，为了方便开发和拓展，我们可以对RpcRequest新增一个属性type

来区分发送的request是正常请求还是心跳检测



krpc-common项目下common.message中

**1.新增RequestType枚举类**

```java
@AllArgsConstructor
public enum RequestType {
    NORMAL(0), HEARTBEAT(1);
    private int code;

    public int getCode() {
        return code;
    }
}
```

2**.RpcRequest新增type属性**

默认为normal，并添加heartBeat()快速构造心跳对象

```java
@NoArgsConstructor
@AllArgsConstructor
@Data
@Builder
public class RpcRequest implements Serializable {
    //v6新增:请求类型
    private RequestType type=RequestType.NORMAL;
    //接口名、方法名、参数列表参数类型
    private String interfaceName;

    private String methodName;

    private Object[] params;

    private Class<?>[] paramsType;
    
    public static RpcRequest heartBeat() {
        return RpcRequest.builder().type(RequestType.HEARTBEAT).build();
    }

}
```

**4.Server端新增逻辑，根据request类型进行处理**

krpc-core项目下com.kama.server.netty下

NettyRpcServerHandler类的channelRead0方法中添加

如果消息类型为心跳，不做处理

```java
@AllArgsConstructor  // 使用 Lombok 自动生成构造器
@Slf4j
public class NettyRpcServerHandler extends SimpleChannelInboundHandler<RpcRequest> {

    private final ServiceProvider serviceProvider;  // 确保通过构造器注入 ServiceProvider

    @Override
    protected void channelRead0(ChannelHandlerContext ctx, RpcRequest request) throws Exception {
        if (request == null) {
            log.error("接收到非法请求，RpcRequest 为空");
            return;
        }
        if(request.getType() == RequestType.HEARTBEAT){
            log.info("接收到来自客户端的心跳包");
            return;
        }
        if(request.getType() == RequestType.NORMAL) {
            //trace记录
            ServerTraceInterceptor.beforeHandle();

            RpcResponse response = getResponse(request);
            //ctx.writeAndFlush(response).addListener(ChannelFutureListener.CLOSE);

            //trace上报
            ServerTraceInterceptor.afterHandle(request.getMethodName());

            ctx.writeAndFlush(response);
        }
    }
```

一些疑问：

**<font style="color:#000000;">1.为什么客户端handler不用主动关闭channel</font>**

<font style="color:#000000;">因为 Channel 是用于服务端和客户端通信的，所以无论哪一方进行了关闭操作，该 Channel 都会关闭的</font>

<font style="color:#000000;"></font>

**<font style="color:#000000;">2.为什么客户端只监听写事件，进行触发心跳包发送的逻辑？</font>**

<font style="color:rgb(77, 77, 77);">客户端channel关闭只需要两种情况：</font>

+ 主动关闭
+ 服务端关闭导致被动关闭

所以，控制客户端只做一件事就可以向服务端传达准确的状态：

+ 开启：按时发送心跳包
+ 关闭：不发心跳包
