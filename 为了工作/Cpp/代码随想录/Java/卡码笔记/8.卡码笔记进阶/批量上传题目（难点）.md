# 批量上传题目

## 背景

在项目中，需要从一段 **Markdown** 格式的文本中，**自动提取**一些面试题信息并将其插入到数据库中。

文本的结构大致如下：

```markdown
# 父分类1

## 子分类A

* 题目1（考点：XXX）【难度】
* 题目2（考点：XXX）【难度】
...

## 子分类B

* 题目X（考点：XXX）【难度】
* ...
...

# 父分类2

## 子分类C

* 题目Y（考点：XXX）【难度】
* ...
```

在这个示例中：

* **一级标题 (Heading level=1)** 表示父分类（如“人工智能”、“Java”、“计算机基础”等）。
* **二级标题 (Heading level=2)** 表示子分类（如“计算机网络”、“操作系统”等隶属于“计算机基础”的子分类）。
* 子分类下的所有 `ListBlock`（一般是无序列表或有序列表）中的每一条 `ListItem`，就对应具体的一道面试题。

每道面试题的 ListItem 格式约定包含：

* **考点**（形如 `(考点：XXX)` 或 `（考点: XXX）`）
* **难度**（形如 `【简单】`、`【中等】`、`【困难】`）
* 备注：这两点缺一不可，都需要匹配，否则直接抛出异常

系统需要将提取到的题目信息，以及父分类、子分类等，**存入数据库**。同时在解析过程中，还要对一些**错误或异常情况**进行处理，例如：

* **无法解析到考点**；
* **无法解析到难度**；
* **重复的题目**（已在数据库中存在同样的题目）；
* **二级标题下没有匹配到任何列表**等等。

## 具体实现

1、**获取原始 Markdown 文本**（例如从文件、接口或直接字符串输入）。

2、**使用 **<code>**flexmark**</code>** 库对 Markdown 进行解析**，得到一个抽象语法树（AST）。

3、遍历 AST：

1. 找到 `Heading level=1`（父分类），并写入/查询数据库，获取父分类 ID。
2. 从该父分类标题后面，依次向下查找 `Heading level=2`（子分类），并写入/查询数据库，获取子分类 ID。
3. 在找到子分类后，寻找后续的 `ListBlock`（无序或有序列表）节点，获取其中的每个 `ListItem`（题目）。
4. 通过正则解析从 `ListItem` 的文本中，提取**考点**和**难度**。
   1. 若解析失败则记录错误。
   2. 若解析成功则获取真正的题目标题（剔除掉括号、难度等标记）。
5. 判断题目是否已存在（重复判断），若存在则报错处理，否则将其插入到数据库。

## 难点

### Markdown 抽象语法树

**难点：**

* 需要深入了解 Markdown 的抽象语法树（AST）结构，有助于确定在解析时如何正确获取不同层级节点。

**解决方案：**

* 可以在 <https://astexplorer.net/> 查看 markdown 生成的抽象语法树。

### 正则解析考点和难度

**难点：**

* 需要从 `(* 题目（考点：XXX）【难度】)` 这类文本中，提取 `examPoint` 和 `difficulty`。
* \*\*\*\*必须保证正则准确匹配中文括号或英文括号的多种情况，并注意其中的**空格、冒号**等可能的差异。

**解决方案：**

* 使用形如 `Pattern.compile("[（(]考点\\s*[：:]\\s*(.*?)[)）]")` 的**宽松匹配**，能处理中英文括号及“：”/“:”的多种用法。
* 同理，难度部分使用 `Pattern.compile("【(.*?)】")` 匹配 `【简单】`、`【中等】`、`【困难】` 等。
* 如果正则匹配不到，则抛出“无法解析到考点”或“无法解析到难度”的错误。

### 解析后标题与重复判断

**难点：**

* 原题目中带有 `(考点...)` 和 `【难度】` 等冗余信息，需要先用正则删去后再 **trim** 得到真正的题目标题。
* 在插入数据库前，需要判断数据库是否已有同标题的题目，以**避免重复插入**。
* 如果**多个空格或特殊符号出现在题目中，可能导致匹配不一致。**

**解决方案：**

* 使用与上面一致的正则去除考点、难度，然后 `String#trim()`；
* 在数据访问层使用`findByTitle`等方法查询题目，若已存在则抛出异常

## 项目实际运营经验

在解析 Markdown 并将题目、分类插入数据库的过程中，难免会遇到各种异常（如正则匹配失败、分类不存在、数据重复等）。针对这些异常处理，可以有两种不同的策略：

#### 部分成功插入（允许脏数据）

**1、实现思路**：

一旦检测到部分题目的解析出现异常，就把这些异常信息记录下来（返回给前端或记录在日志中），同时对能正常解析的题目和分类继续插入数据库。

**2、优点**：

不会阻塞整批数据的落库流程，对于能正常解析的内容可以立即使用。

**3、缺点**：

由于一些已插入的记录与异常记录是混杂存在的，当我们修复异常后（比如修正 Markdown 文本）再导入时，很可能与之前已插入的数据形成冲突，需要再次手工去清理或更新数据库中的脏数据；而手动修改数据库往往**成本高且容易出错**。

#### 遇到异常则回滚（统一保持一致性）

**1、实现思路**：

若在解析或插入过程中发现异常，则**终止整个导入并回滚**数据库事务，拒绝任何不完整或错误的数据进入数据库。前端得到的仅是一条“插入失败”或相应错误原因的提示。

**2、优点**：

数据库中的数据始终保持完整一致，不会留有不正确或不完整的记录。只要修正了 Markdown 文本的错误后，再次发起导入即可，无需再清理或修改先前插入的记录。这样对**维护和追踪**更简洁有效。

**3、缺点**：

若只是个别题目存在轻微错误，也会导致整批插入被回滚，需要重新提交，短期看会有些许操作上的不便。

综上，在实际生产环境中，第二种**回滚式处理**通常更加稳妥，避免了脏数据的遗留和复杂的数据库清理，后续只需要根据错误提示去修正 Markdown 文本，再次发起导入即可。
