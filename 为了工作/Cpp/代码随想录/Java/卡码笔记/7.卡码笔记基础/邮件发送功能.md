# 邮件发送功能

<font style="color:rgb(51, 51, 51);">在很多系统中，邮件发送功能是很常见也很基础的功能。本节将会介绍怎么在 SpringBoot 项目中集成邮件发送功能。集成后我们会以“用户注册时通过邮箱进行验证”为案例进行一次简单的功能实践。</font>

# 集成邮箱发送功能

## 基本思路

简单对照一下现实世界发送邮件的步骤，我们至少需要两样“东西”：

1. 一个邮局，用于发送邮件
2. 一个地址，用于接收邮件

地址当然是别人提供了，比如用户注册的时候，提供的个人邮箱。

邮局就需要我们自己创建。

作为世界上最好用的后端开发框架，SpringBoot 肯定已经帮我们把最麻烦的功能都完成了，我们只需要填填配置文件就好了，并且像真正干活，去执行发送邮件的这种功能，肯定是找一些第三方服务，例如 QQ 邮箱。

## QQ 邮箱配置实践

发送邮件的第三方服务有很多，QQ 邮箱每个人都有，使用起来最方便。

首先看一下配置文件怎么写的，这一段配置文件在 kamanote 项目的 application.yaml 中可以找到。

```plain
spring:
  mail:
    host: smtp.qq.com               # QQ 邮箱第三方服务的服务器
    port: 465                       # 端口号
    username: your@qq.com           # 发送邮件的 QQ 邮箱号
    password: xxxxxxxx              # 授权码（不是 QQ 密码！！！，这里需要自己去申请）
    protocol: smtps                 # 协议：加了 SSL 的 SMTP
    default-encoding: UTF-8         # 编码格式
    properties:
      mail:
        smtp:
          auth: true               # 开启身份认证
          ssl:
            enable: true           # 开启 SSL 加密
```

在这段配置文件中，**只有 username 字段和 password 字段是需要我们自定义的**，其它的默认就可以，下面我们来看一下这两个字段应该怎么配置。

# 实现邮箱注册验证功能

## 基本流程

一个最基本的邮箱验证的流程如下：

1. 用户输入邮箱
2. 发送验证码
3. 用户输入验证码
4. 验证并且完成注册

![1739972100846-2490fa19-40a3-4b0d-8f5d-e0ea3cc22675.png](./img/g_Gol4Qevt_3l6zu/1739972100846-2490fa19-40a3-4b0d-8f5d-e0ea3cc22675-446757.png)

## 验证码存储

**1、存储方案分析**

对于验证码这种实效性很强的数据，**本来就是几分钟内不使用就过期的数据**，并不**需要进行持久化**处理，所以很适合存储在 redis 中，并且通过 redis 的 TTL 的特性，可以很自然的实现过期的功能。

**2、Redis 键值设计**

* key 的格式设计：email:{type}:{identifier}
* value 的格式设计："193933"，六位数字；太短了容易被暴力破解，太长了用户输入体验不好
* 过期时间：5 分钟（2 分钟到 10 分钟内都可以，可以根据具体业务适当延长或者缩短）
* 验证后立即删除验证码

> tips：**关于 key值设计的一点良好实践：**
>
> 使用冒号 `:` 进行层级分隔（参考命名空间），进行结构化的设计。
>
> 例如：
>
> * user:profile:12345（用户 ID 为 12345 的简介）
> * article:like:29393（文章 ID 为 29393 的点赞数）
>
> **这种设计方案，有以下三个好处：**
>
> 1. 能够直观的看到 key 对应的 value 的用途是什么
> 2. 能够防止 key 值冲突
> 3. 还能够根据 key 值的前缀进行批量的数据处理。
>
> 现在来看，我们上面设计的用于存储验证码的 key 值会有以下的可能结果：
>
> * email:register\_verification\_code:2343233@qq.com
> * email:login\_verification\_code:92939393@qq.com

## 功能设计分析

1. 发送邮件属于 IO 密集型的操作，响应延迟很高
2. 本项目属于体量比较小的项目，没有引入 Kafka 或者其他消息队列的必要
3. 需要防止别人一直刷发送验证码的接口

针对以上三点，可以\*\*设计一个 “基于 Redis 消息队列” 的轻量级的异步任务机制，\*\*用于实现邮件的发送工作。

**具体设计思路如下：**

* 使用 Redis 的 List 的 left push 和 right pop 模拟一个简单的消息队列，将待发的邮件存储在这个消息队列中
* 创建一个定时任务，每隔一段时间检查和处理一下 Redis 中用于存储待发邮件的 List

> 定时任务的时间不能太长，会造成用户明显的延迟感知，太短了对 Redis 的压力又很大

**接口防刷的设计思路如下：**

* 利用 Redis 的 String 存储不同邮箱的限流标记，支持过一段时间后自动过期

## 功能实现代码

这部分的功能实现，顺序按照用户点击发送验证码的按钮开始，到实现验证码的验证结束。

### 创建 EmailController

功能：发送注册验证码

方法：`GET`

路径：`/api/email/verify-code`

```java
@RestController
@RequestMapping("/api/email")
public class EmailController {
    @Autowired
    private EmailService emailService;
    
    @GetMapping("/verify-code")
    public ApiResponse<Void> sendVerifyCode(@RequestParam 
                                            @NotBlank 
                                            @Email String email) {
        try {
            // 调用 emailService 提供的发送验证码服务
            emailService.sendVerificationCode(email);
            return ApiResponseUtil.success(null);
        } catch (Exception e) {
            return ApiResponseUtil.error(e.getMessage());
        }
    }
}
```

`EmailController` 主要负责接收请求并调用对应的 Service 方法，核心的逻辑都在下文的 `EmailService`内。

### 创建 EmailService 接口

在创建 `EmailService`接口之前，我们需要先明确 `EmailService` 接口应该提供的功能。

1. 发送验证码功能
2. 校验验证码是否正确
3. 判断邮箱是否被限制发送邮件

明确 `EmailService` 接口的应该包含的功能后，开始分析接口中应该包含哪些方法，每个方法都需要什么参数，返回值应该返回什么。

**最终设计的接口如下：**

```java
public interface EmailService {
    /**
     * 发送验证码邮件
     *
     * @param email 目标邮箱
     * @return 发送的code
     * @throws RuntimeException 如果发送邮件失败，将抛出异常
     */
    String sendVerificationCode(String email);

    /**
     * 校验验证码是否正确
     *
     * @param email 邮箱地址
     * @param code 用户输入的验证码
     * @return true 表示校验通过，false 为不通过
     */
    boolean checkVerificationCode(String email, String code);

    /**
     * 判断邮箱当前是否处于验证码限流状态
     *
     * @param email 邮箱地址
     * @return true 表示当前已限流，不可发送，false 表示未限流，可以发送
     */
    boolean isVerificationCodeRateLimited(String email);
}
```

#### sendVerificationCode 方法和 “EmailTaskConsumer”

到这里，我们可以开始实现一个“**基于 Redis 消息队列**” 的轻量级异步任务机制了。

消息队列有两个最基础的部分：

1. 生产者
2. 消费者

从代码层面来说，`sendVerificationCode` 就是所谓的生产者。

**生产者的工作步骤：**

1. 接收 email 参数，生成一个 email 对应的 code
2. 将 email、code、以及当前的时间戳封装为一个对象（EmailTask 对象）
3. 将 EmailTask 对象序列化为 JSON 字符串（Redis 只支持存储字符串）
4. 将 JSON 字符串写入到消息队列中
5. 防止重复请求，给邮箱设置一个限流键（这步可以不包含在 `sendVerificationCode` 中）

**消费者的工作步骤：**

1. 每隔一段时间轮询 Redis，查看消息队列中是否存在任务
2. 将任务的 JSON 字符串从消息队列中取出，将其反序列化为 EmailTask 对象
3. 根据 EmailTask 对象中的字段，填充 SimpleEmailMessage 对象
4. JavaMailSender 发送 SimpleEmialMessage 对象（调用第三方服务，发邮件给用户）

到这里，生产者和消费者需要完成的步骤已经规划完毕，接下来我们看具体代码实现。

**生产者部分：**

首先是 EmailTask 对象，拥有三个字段

1. email 字段：用户的 email
2. code：验证码
3. timestamp：时间戳

```java
@Data
public class EmailTask {
    private String email;
    private String code;
    private long timestamp;
}
```

接下来是 `sendVerificationCode` 的实现：

```java
@Override
public String sendVerificationCode(String email) {
    // 检查发送频率
    if (isVerificationCodeRateLimited(email)) {
        throw new RuntimeException("验证码发送太频繁，请 60 秒后重试");
    }

    // 生成6位随机验证码
    String verificationCode = RandomCodeUtil.generateNumberCode(6);

    // 实现异步发送邮件的逻辑
    try {

        // 创建邮件任务
        EmailTask emailTask = new EmailTask();

        // 初始化邮件任务内容
        // 1. 邮件目的邮箱
        // 2. 验证码
        // 3. 时间戳
        emailTask.setEmail(email);
        emailTask.setCode(verificationCode);
        emailTask.setTimestamp(System.currentTimeMillis());

        // 将邮件任务存入消息队列
        // 1. 将任务对象转成 JSON 字符串
        // 2. 将 JSON 字符串保存到 Redis 模拟的消息队列中
        String emailTaskJson = objectMapper.writeValueAsString(emailTask);
        String queueKey = RedisKey.emailTaskQueue();
        redisTemplate.opsForList().leftPush(queueKey, emailTaskJson);

        // 设置 email 发送注册验证码的限制
        String emailLimitKey = RedisKey.registerVerificationLimitCode(email);
        redisTemplate.opsForValue().set(emailLimitKey, "1", limitExpireSeconds, TimeUnit.SECONDS);

        return verificationCode;
    } catch (Exception e) {
        log.error("发送验证码邮件失败", e);
        throw new RuntimeException("发送验证码失败，请稍后重试");
    }
}
```

**消费者部分（EmailTaskConsumer）：**

```java
@Component
public class EmailTaskConsumer {
    
    @Autowired
    private JavaMailSender mailSender;

    @Autowired
    private ObjectMapper objectMapper;

    @Autowired
    private RedisTemplate<String, String> redisTemplate;

    @Value("${spring.mail.username}")
    private String from;

    // 每 3 秒轮询一次 redis，查看是否有待发的邮件任务
    @Scheduled(fixedDelay = 3000)
    public void resume() throws JsonProcessingException {
        String emailQueueKey = RedisKey.emailTaskQueue();

        // 从队列中取任务对象
        while (true) {

            // 获取任务对象
            String emailTaskJson = redisTemplate.opsForList().rightPop(emailQueueKey);

            if (emailTaskJson == null) {  // 队列中没有任务对象，退出本次执行
                break;
            }

            // 将 redis 中的 JSON 字符串转成 emailTask 对象
            EmailTask emailTask = objectMapper.readValue(emailTaskJson, EmailTask.class);
            String email = emailTask.getEmail();
            String verificationCode = emailTask.getCode();

            // 根据 emailTask 对象中的信息
            // 填充 SimpleMailMessage 对象，然后使用 JavaMailSender 发送邮件
            SimpleMailMessage mailMessage = new SimpleMailMessage();
            mailMessage.setFrom(from);
            mailMessage.setTo(email);
            mailMessage.setSubject("卡码笔记- 验证码");
            mailMessage.setText("您的验证码是：" + verificationCode + "，有效期" + 5 + "分钟，请勿泄露给他人。");

            mailSender.send(mailMessage);

            // 保存验证码到 Redis
            // 有效时间为 5 分钟
            redisTemplate.opsForValue().set(RedisKey.registerVerificationCode(email), verificationCode, 5, TimeUnit.MINUTES);
        }
    }
}
```

#### checkVerificationCode 方法的实现

`checkVerificationCode` 的实现逻辑很简单，根据用户的 email 查询出 redis 中存储的 code，和用户输入的 code，比较是否相等。

在验证成功后需要将 Redis 中的记录删除。

```java
@Override
public boolean checkVerificationCode(String email, String code) {
    String redisKey = RedisKey.registerVerificationCode(email);
    String verificationCode = redisTemplate.opsForValue().get(redisKey);

    if (verificationCode != null && verificationCode.equals(code)) {
        redisTemplate.delete(redisKey);
        return true;
    }
    return false;
}
```

#### isVerificationCodeRateLimited 的实现

检查 Redis 中是否存在 email 对应的限流键，存在则返回 true 表示已被限流。

```java
@Override
public boolean isVerificationCodeRateLimited(String email) {
    String redisKey = RedisKey.registerVerificationLimitCode(email);
    return redisTemplate.opsForValue().get(redisKey) != null;
}
```
