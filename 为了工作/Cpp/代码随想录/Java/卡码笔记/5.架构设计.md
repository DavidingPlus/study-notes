# 角色分析
+ 读者：浏览笔记的普通用户
+ 作者：发布笔记的用户
+ 管理员：整个系统的超级管理

## 权限划分图
![1734491534843-a746c5db-199a-4f7d-a8f9-2f42813ff790.png](./img/IGoFtgHZSOEbkRiN/1734491534843-a746c5db-199a-4f7d-a8f9-2f42813ff790-577316.png)

基于以上，我们把卡码笔记用户分为两类：

+ 普通用户：作为卡码笔记注册用户，围绕笔记展开一系列业务。
+ 管理员：作为官方，负责整个系统的运营。

# 业务分析
咱们的笔记系统可以按照业务划分为

+ 用户
+ 笔记
+ 题库
+ 题单

![1734504356783-ec929a81-f675-450c-ac15-5546699b44f5.png](./img/IGoFtgHZSOEbkRiN/1734504356783-ec929a81-f675-450c-ac15-5546699b44f5-711546.png)

根据我上图的总结分析：

+ 题库：实际上分类和笔记功能点基于题库。
+ 点赞、收藏、技术统计
    - 这种与业务相关，但是可以考虑抽离业务之外的独立存在，可以考虑建设通用的服务能力。

独立于核心业务之外的功能：

+ 搜索、推荐、排行榜
+ 卡码笔记社区运营
