## 1.1 项目描述模板
### 1.1.1 标准格式
```plain
项目名称：JChatMind - 智能 AI Agent 系统

项目时间：2024.XX - 2024.XX

项目角色：核心开发 / 架构设计 / 技术负责人

项目描述：
基于 Spring AI 框架构建的智能 AI Agent 系统，实现了自主决策、工具调用和知识库检索功能。
系统采用 Think-Execute 循环机制，支持多模型切换、RAG 检索和实时通信，能够完成复杂的多步骤任务。

技术栈：
Spring Boot 3.5.8、Spring AI 1.1.0、PostgreSQL、pgvector、MyBatis、React、SSE

主要职责：
1. 设计并实现 Agent 核心引擎，包括 Think-Execute 循环和状态管理
2. 实现工具调用系统，支持固定工具和可选工具的灵活配置
3. 基于 RAG 技术实现知识库检索功能，使用 pgvector 进行向量相似度搜索
4. 设计多模型支持架构，实现 ChatClientRegistry 注册表模式
5. 实现 SSE 实时通信，支持 Agent 执行状态的实时推送
6. 设计 RESTful API 和统一响应格式，提供完整的后端服务

项目成果：
- 实现了完整的 AI Agent 系统，支持工具调用和知识库检索
- 支持 DeepSeek、智谱AI 等多种大语言模型，可灵活切换
- 实现了向量数据库检索
```

+ ✅ 支持 Markdown 文档解析和分块

**3. 多模型支持**

+ ✅ 注册表模式实现模型动态切换
+ ✅ 支持 DeepSeek、智谱AI 等多种模型

### 1.7.2 "项目有什么难点？"
**回答模板**：

```plain
主要难点有以下几个：

1. **Think-Execute 循环实现**：需要理解 Agent 的工作机制，设计合理的循环流程
   - 解决方案：参考 ReAct 论文，设计状态机管理循环流程

2. **向量类型处理**：PostgreSQL 的 vector 类型需要自定义 TypeHandler
   - 解决方案：实现 PgVectorTypeHandler，处理向量序列化和反序列化

3. **工具调用流程**：需要手动控制工具调用，避免 Spring AI 自动执行
   - 解决方案：禁用自动执行，使用 ToolCallingManager 手动管理

4. **多模型支持**：需要设计灵活的模型切换机制
   - 解决方案：使用注册表模式，统一管理多个 ChatClient
```
