# 2. 本项目需要的基础

## 完成本项目需要多久
不同基础的同学完成本项目周期会有明显差异，下面给出大体列一下：

| 学员基础类型 | 典型背景 | 项目完成周期 | 完成方式说明 |
| --- | --- | --- | --- |
| **具备 Go 基础 + 做过 Web 开发** | 后端开发/转语言同学 | **2~5 天** | 直接跟代码，可快速掌握 rpc相关知识 |
| **做过C++/Java语言的RPC框架但不熟悉Go** | Java / Python / Node / C++ RPC框架 | **5~7 天** | 用 2~4 天熟悉 Go 语法,后续直接跟项目即可(因为有基础) |
| **只有算法或刷题基础，但无后端经验** | 刷过 LeetCode / 有编程基础的学生 | **7~14 天** | 从 HTTP/REST、rpc、逐步带入，完成节奏可控 |
| **完全从零开始 Web 开发** | 没做过项目的新手 | **14-21 天** | 按课程安排由浅入深，重点在7.梳理部分的各模块内容 |




## 开发本项目需要的技术基础（kamaRPC-Go RPC 框架）
本项目面向希望深入理解分布式系统与底层网络通信机制的开发者。**项目从基础通信模型到完整服务治理体系逐步构建，强调工程化实现与架构设计能力，因此不要求一开始完全掌握所有内容**,**可以边看边学**，但需要具备一定的系统编程思维。

## 1. Go 语言基础（必要）
需要达到能够阅读与编写基础业务逻辑的水平，包括：

| 知识点 | 要求说明 |
| --- | --- |
| Go 基础语法 | 结构体、接口、指针、方法接收者、错误处理 |
| 并发模型 | goroutine、channel、sync.Mutex、WaitGroup |
| context 机制 | timeout、deadline、cancel 的使用与传播 |
| 模块管理 | 熟练使用 go mod，理解多包结构组织 |


不要求深入 runtime 原理，但需要能理解并发安全问题与协程调度行为。



## 2. 网络编程基础（核心能力）
RPC 框架本质是网络框架，因此需要具备基本网络知识：

| 知识点 | 要求说明 |
| --- | --- |
| TCP 基础 | 三次握手、四次挥手、长连接概念 |
| 粘包/拆包 | 理解为什么会出现半包与粘包 |
| Socket 编程 | 能理解 net.Conn 读写循环 |
| IO 模型 | 阻塞 IO 概念即可，不要求 epoll 深入 |


## 3. 序列化与数据编码
RPC 的核心之一是数据编解码能力：

| 技术 | 要求说明 |
| --- | --- |
| JSON | 理解 Marshal/Unmarshal |
| Protobuf | 知道 proto 定义与生成代码流程 |
| 二进制协议 | 理解字节序、binary 编码方式 |


不要求手写 protobuf 编译器，但需要理解序列化与性能的关系。

## 4. 分布式系统基础（重要）
本项目涉及服务注册、负载均衡与稳定性治理，需要理解基本概念：

| 知识点 | 要求说明 |
| --- | --- |
| 服务注册与发现 | 理解注册中心存在的意义 |
| 负载均衡 | 轮询、随机、权重、一致性哈希 |
| 熔断/限流 | 错误率、滑动窗口、令牌桶模型 |


不要求深入 CAP 理论或分布式一致性算法，但需要理解“节点可能会失败”这一基本假设。

## 5. 注册中心与服务发现（实践能力）
本项目使用：

etcd

需要了解：

| 知识点 | 要求说明 |
| --- | --- |
| lease 机制 | TTL 与 keepalive 的意义 |
| watch 机制 | 如何监听 key 变化 |
| 客户端 API | 基本使用即可 |
