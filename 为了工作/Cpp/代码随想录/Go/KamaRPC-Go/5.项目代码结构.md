# KamaRPC-Go 项目代码结构与调用关系（从入口到一次 RPC 调用）

KamaRPC-Go 的代码组织非常清晰：用 `cmd/` 放示例入口，用 `internal/` 放框架核心实现，用 `pkg/` 放对外业务 API（示例服务与参数结构体）。

## 2. “入口”在哪里？先看 cmd/ 三个 main

### 2.1 服务端入口 1：`cmd/server1/server1_example.go`

它做了 4 件事：

1. 创建 etcd registry：`registry.NewRegistry(["localhost:2379"])`
2. 创建 RPC Server：`server.NewServer(":9090", WithServerCodec(JSON))`
3. 注册本地服务（反射调用用）：
   * `srv.Register("Arith", &api.Arith{})`
   * `srv.Register("Arith2", &api.Arith2{})`
4. 将服务实例注册到 etcd：`reg.Register(serviceName, Instance{Addr}, ttl)`
5. `srv.Start()` 开始监听 TCP + Accept 新连接

读者理解：**server1 是一个真实的 RPC Provider 节点**，并把自身地址写入 etcd，供 client 发现。

***

### 2.2 服务端入口 2：`cmd/server2/server2_example.go`

和 server1 类似，只是端口是 `:9091`，只注册 `Arith` 服务。\
用于演示**多实例 + 负载均衡/服务发现**。

***

### 2.3 客户端入口：`cmd/client/client_example.go`

它做了 3 件核心事：

1. 创建 registry（连 etcd）
2. 创建 client：`client.NewClient(reg, WithClientCodec(JSON))`
3. 每 5 秒发起一轮请求：每轮并发发送 3 个 `InvokeAsync`，然后等待 `Future` 完成并取结果。

读者理解：client 示例重点演示了**异步调用（Future）**、**多路复用 requestId**、以及**服务发现 + 负载均衡选址**。

***

## 3. 模块分层：KamaRPC-Go 的“框架骨架”

你可以把内部实现理解为下面这条链：

* **client/server（调用层）**
  * 负责：参数序列化、构建请求、超时控制、熔断限流、选择节点、发包/收包、返回 Future/结果
* **protocol（协议层）**
  * 负责：定义 Header + 二进制 Message 格式，Encode/Decode
* **transport（传输层）**
  * 负责：TCP 长连接、粘包/半包处理、并发请求响应映射（requestId -> Future）、连接池
* **codec（编解码与压缩）**
  * 负责：JSON/Protobuf 序列化 + gzip 压缩/解压（可插拔注册）
* **registry/loadbalance（服务治理）**
  * 负责：etcd 注册发现 + Watch 动态更新 + LB 选节点
* **breaker/limiter（稳定性）**
  * 负责：熔断器状态机 + 令牌桶限流

***

## 4. 一次 RPC 调用的完整链路（按代码真实路径走）

下面用“客户端调用 Arith.Add”为例，按**真实调用路径**把关键文件串起来：

### 4.1 Client 发起调用：`internal/client/client.go`

入口函数：

* 异步：`Client.InvokeAsync(ctx, service, method, args) -> *transport.Future`
* 同步：`Client.Invoke(...)`（本质是 InvokeAsync + 等待 Future）

调用过程（非常关键）：

1. **客户端限流**：`c.limiter.Allow()`（`internal/limiter/token_bucket.go`）
2. **服务发现**：`c.reg.Discover(service)`（`internal/registry/registry.go`）
3. **负载均衡选址**：`c.lb.Select(instances)`（`internal/loadbalance/*`）
4. **熔断判断**：`br.Allow()`（`internal/breaker/breaker.go`）
5. **连接池取连接**：`pool.Acquire(ctx)`（`internal/transport/tcp_connection_pool.go`）
6. **序列化 args**：`c.codec.Marshal(args)`（`internal/codec/*`）
7. **组装协议 Message**：`protocol.Message{Header, Body}`（`internal/protocol/*`）
8. **发送并返回 Future**：`conn.SendAsync(req)`（`internal/transport/tcp_client.go`）
9. **Future 完成回调更新熔断统计**：`future.OnComplete(...)`

对读者来说：client 这一层是“治理 + 组包 + 发包”的总控中心。

***

### 4.2 传输层多路复用：`internal/transport/tcp_client.go`

核心点：**requestId -> Future 映射表**（多路复用关键实现）

* `SendAsync`：
  * `seq := nextSeq()` 生成 requestId
  * `pending.Store(seq, future)` 保存映射
  * `conn.Write(msg)` 写入 TCP
  * 写失败会调用 `fail(err)`：关闭连接 + 让所有 pending Future 都失败（避免“旧连接复用导致异常”）
* `readLoop`（后台 goroutine）：
  * 循环 `conn.Read()` 读到响应 Message
  * 根据 `msg.Header.RequestID` 找到对应 Future
  * `future.Done(msg.Body, err)` 完成 Future，唤醒等待方

对读者来说：**真正的“单连接并发请求”能力就在这里**。

***

### 4.3 TCP 粘包/半包处理：`internal/transport/tcp_connection.go`

`TCPConnection.Read()` 的逻辑是“边读边拼包”：

* 先把 socket 读到的字节写入 `PacketBuffer`
* `PacketBuffer.Read()` 检查是否够一个完整包：
  * 最小包头 10 字节
  * 解析 `headerLen` / `bodyLen`
  * 如果 buf 里不够 `10 + headerLen + bodyLen`，继续读
  * 够了就切出完整 packet，并“移动窗口”（把已消费的字节从缓冲区移除）
* packet 交给 `protocol.Decode(packet)` 得到 `protocol.Message`

对读者来说：这里解决了 TCP 的**流式传输边界问题**（粘包、拆包、半包）。

***

### 4.4 协议编码/解码：`internal/protocol/message.go + header.go`

协议格式是：

```plain
Magic(2B) + HeaderLen(4B) + BodyLen(4B) + HeaderBytes + BodyBytes
```

* `Encode`：
  * Body 如果标记了压缩（如 gzip）会先压缩
  * Header 使用 JSON 编码（Header 是框架元信息：service/method/requestId/error/compress…）
  * 最终拼成二进制包
* `Decode`：
  * 校验 Magic
  * 解析 headerLen/bodyLen
  * 解 header（JSON）
  * 解 body（如 gzip 则解压）
  * 返回 `Message{Header, Body}`

对读者来说：**Header 是控制面，Body 是数据面**。

***

### 4.5 Server 收包、限流、反射调用：`internal/server/server.go + handler.go`

**server.go**：

* `Start()`：`net.Listen` + `Accept()`，每个新连接包一层 `transport.NewTCPConnection`，然后 `go s.Handle(tcpConn)`
* `Handle(conn)`：
  * 循环 `conn.Read()` 收请求
  * **服务端限流**：`s.limiter.Allow()`，不允许就返回 error 响应
  * 找到本地注册的 service：`s.services[msg.Header.ServiceName]`
  * 调用 `s.handler.Process(conn, msg, serviceImpl)`

**handler.go**（最关键：反射调用）：

* `Process(...)`：
  * `invoke(...)` 反射找到方法并执行
  * 把结果 marshal 成 body（JSON/PROTO 取决于 handler codec）
  * 写回响应：`protocol.Message{RequestID, Error?, Body}`
* `invoke(...)` 当前支持一种经典 net/rpc 风格签名：

```plain
func(req *Req, reply *Resp) error
```

它会：

```
1. 反射拿到方法
2. new 一个 req，并把 Body 反序列化进去
3. new 一个 reply
4. `method.Call(req, reply)`
5. 返回 reply 作为响应数据
```

对读者来说：**Server 的“服务注册”其实就是把 struct 实例放到 map 里，真正的分发靠反射 MethodByName**。

***

## 5. 服务发现与动态更新：`internal/registry/registry.go`

Registry 做了两层机制：**首次 Get + 后台 Watch 增量更新 + 本地缓存**。

* `Register(service, instance, ttl)`：
  * etcd Grant Lease
  * Put `/kamaRPC/services/{service}/{addr}` = `addr` 并绑定 lease
  * KeepAlive 续租（后台 goroutine）
* `Discover(service)`：
  * 如果本地缓存已有，直接返回缓存
  * 否则 `initService(service)`：
    * `Get(prefix, WithPrefix())` 拿到全量实例
    * 写入本地 map 缓存
    * `go watch(service)` 启动监听增量变化
* `watch(service)`：
  * Watch 前缀 key
  * PUT：新增/更新实例到缓存
  * DELETE：从缓存移除实例
  * watch 断线后 sleep 1s 重连（简单但有效）

对读者来说：这就是一个典型的“**注册中心 + 本地缓存 + watch 保持更新**”实现模型。

***

## 6. 负载均衡：`internal/loadbalance/*`

* `balancer.go` 定义统一接口：

```plain
type LoadBalancer interface {
    Select([]registry.Instance) registry.Instance
}
```

* `round_robin.go`：轮询
* `random.go`：随机
* `weighted_rr.go`：平滑加权轮询（Weighted Round Robin）

注意：`WeightedRR` 需要 weights 数量与实例数量一致，否则直接返回空实例（这里是一个“演示版约束”，生产级通常会做动态权重映射）。

***

## 7. 熔断与限流：`internal/breaker/*` + `internal/limiter/*`

### 7.1 熔断器 `breaker/breaker.go`

* 三态：Closed / Open / HalfOpen
* `Allow()`：
  * Closed：放行
  * Open：超时后切 HalfOpen，否则拒绝
  * HalfOpen：只允许一个探测请求
* `RecordFailure/RecordSuccess`：根据窗口失败率进入 Open，或探测成功回到 Closed

### 7.2 令牌桶 `limiter/token_bucket.go`

* `NewTokenBucket(rate)`：按固定速率补充 tokens
* `Allow()`：有 token 则放行，否则限流

客户端和服务端都各自做了一层限流（client.go / server.go 中都能看到）。

## 9. 建议录友们读代码路线

如果你是第一次读 KamaRPC-Go，按这个顺序最省时间：

1. **先跑起来**：看 `cmd/server1`、`cmd/server2`、`cmd/client` 三个示例
2. **先把请求链路串起来**：
   * `internal/client/client.go`（InvokeAsync 从这里开始）
   * `internal/transport/tcp_client.go`（requestId -> Future 多路复用）
   * `internal/transport/tcp_connection.go`（粘包/半包处理）
   * `internal/protocol/message.go`（协议 Encode/Decode）
3. **再看服务端如何执行**：
   * `internal/server/server.go`（Accept/Handle/限流）
   * `internal/server/handler.go`（反射调用 + 写回响应）
4. **最后看治理能力**：
   * `internal/registry/registry.go`（etcd 注册发现 + watch）
   * `internal/loadbalance/*`（RR/Random/WRR）
   * `internal/breaker/*`（熔断状态机）
   * `internal/limiter/*`（令牌桶）
