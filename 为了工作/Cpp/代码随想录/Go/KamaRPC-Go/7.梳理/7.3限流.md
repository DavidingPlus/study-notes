# 7.3 限流

# 限流
```go
if !c.limiter.Allow() {
    return nil, errors.New("rate limit exceeded")
}

```

在代码中,有封装这么一个函数, 这一步是在做客户端限流

## 为什么要限流？
假设：服务器最多只能处理 1000 QPS , 但是你一秒发 5000 请求

可能会导致: 服务雪崩/CPU 飙满/延迟暴涨/所有请求都变慢

所以限流的本质是：**在客户端控制流量，保护服务端**

**当然,限流机制不仅仅有在客户端做,服务端也有做,我们本章节先讲解客户端相关的函数调用**

## 限流代码封装讲解:
限流我们使用的是**令牌桶**

核心思想:

+ 系统每秒生成 N 个令牌
+ 每个请求需要拿到 1 个令牌才能执行
+ 没有令牌，请求就被拒绝

假设一开始的rate是1000,这边在初始化的时候会开启一个协程, 定时(如1s)会去补充桶里的令牌数量,恢复成原先的rate个(会直接恢复满,也可以慢慢地恢复上去

而Allow函数就是判断当前桶中有令牌

如果有就会扣减一个,允许进行请求,如果没有就会拒绝当前请求

```go
package limiter

import (
	"sync"
	"time"
)

type TokenBucket struct {
	tokens int   //当前桶里的令牌数量
	rate   int //每秒补充的令牌数量
	mu     sync.Mutex //保证并发安全
}

func NewTokenBucket(rate int) *TokenBucket {
	tb := &TokenBucket{tokens: rate, rate: rate}
	go func() {
		for {
			time.Sleep(time.Second)
			tb.mu.Lock()
			tb.tokens = tb.rate
			tb.mu.Unlock()
		}
	}()
	return tb
}

func (tb *TokenBucket) Allow() bool {
	tb.mu.Lock()
	defer tb.mu.Unlock()
	if tb.tokens > 0 {
		tb.tokens--
		return true
	}
	return false
}

```
