# 7.2负载均衡

# 为什么需要负载均衡?
在后端系统中, 如果只有一台服务器, 那么所有的请求都打到这台机器

当访问量变大的时候,会出现响应变慢、CPU 爆满、内存打满

所以我们一般会部署多台服务器, 把请求分发给不同的机器

这是需要负载均衡的原因

在多个服务实例之间，合理地分配请求流量

比如你有 3 台服务 A、B、C, 客户端每次发请求时，需要决定：发给 A？还是发给 B？还是发给 C？

这个选择规则,就是负载均衡算法

# 负载均衡代码讲解
结合项目中的负载均衡来看,有三种算法,他们都实现了Select这个接口的方法

```cpp
package loadbalance

import "kamaRPC/internal/registry"

type LoadBalancer interface {
	Select([]registry.Instance) registry.Instance
}

```

下面我们依次讲解

## 随机算法:
最简单的方式之一, 每次随机选一个, 优点简单实现容易. 但是缺点就是短时间可能全打到同一台服务器

代码实现如下:

```cpp
type Random struct {
	r *rand.Rand
	m sync.Mutex
}

func NewRandom() *Random {
	return &Random{
		r: rand.New(rand.NewSource(time.Now().UnixNano())),
	}
}

func (r *Random) Select(list []registry.Instance) registry.Instance {
	if len(list) == 0 {
		return registry.Instance{}
	}

	r.m.Lock()
	defer r.m.Unlock()
	return list[r.r.Intn(len(list))]
}

```

## 轮询算法:
针对上述所说的3台服务器,利用轮询算法.那么会按照顺序的一个一个选

流程如下

```cpp
A → B → C → A → B → C
```

代码如下:

```cpp
type RoundRobin struct {
	idx uint64
}

func NewRR() *RoundRobin {
	r := &RoundRobin{}
	return r
}

func (r *RoundRobin) Select(list []registry.Instance) registry.Instance {
	i := atomic.AddUint64(&r.idx, 1)
	return list[i%uint64(len(list))]
}

```

优点是非常均匀、简单稳定

但是这种缺点也很明显,就是没有考虑到机器之间性能的差异. 假设A服务器性能更高,那么理应它的承受能力也是最高的, 多请求应该分配给它

所以这也就有了下面的加权轮询算法

## 加权轮询算法(重点):
如果A机器很强,而B一般,C很弱,那么我们可以设置权重

例如

```go
A: 5
B: 3
C: 1
```

此时,由于A占比为5/9, 那么每9次,按道理会出现5次, 而B是3次, C是1次.

此时A就扛住了更多的请求,合理考虑到了机器的性能. 这就是加权轮询

但是普通的加权轮询依旧会有些问题:

如果权重是A:5 B:1 , 那么普通加权轮询可能就是

```go
A A A A A B
```

当有6个请求过来的时候,会有5个请求连续落到A上

请求非常不平滑, 可能在一瞬间压垮某台机器. 所以在代码中我们进行了一些修改, 更改成平滑加权轮询算法,我们先来了解一下它的请求结果是什么? 

可能如下:

```go
A A B A A A
```

而不是原先的

```go
A A A A A B
```

让请求没有那么连续地打在同一台机器上, 缓解了部分压力, 这就更平滑了, 这就是平滑加权轮询算法

下面我们看看代码实现:

重点在于代码注释的三个步骤: 这边会每次选择完节点都减去一个总权重

如果不减, 那么它的权重会继续最大, 而减去总权重, 可以让被选节点的优势进行一定的消耗, 保证其他节点的当前权重有机会追上, 即在下一次其他节点选择的可能性会更大

这种做法,保证了长期比例符合权重, 且在短期分配又足够平滑

```go
// 平滑权重轮询算法
type WeightedRR struct {
	mu            sync.Mutex
	weights       []int // 固定权重
	currentWeight []int // 当前权重（动态变化）
	totalWeight   int   // 权重总和
}

// 初始化
func NewWeightedRR(weights []int) *WeightedRR {
	w := &WeightedRR{
		weights:       make([]int, len(weights)),
		currentWeight: make([]int, len(weights)),
	}

	copy(w.weights, weights)

	total := 0
	for _, wt := range weights {
		if wt < 0 {
			wt = 0
		}
		total += wt
	}
	w.totalWeight = total

	return w
}

func (w *WeightedRR) Select(list []registry.Instance) registry.Instance {
	if len(list) == 0 {
		return registry.Instance{}
	}

	w.mu.Lock()
	defer w.mu.Unlock()

	// 如果实例数量变化，说明需要重置(这边直接返回一个空了)
	if len(list) != len(w.weights) {
		log.Println("实例数量和权重列表数量不一致")
		return registry.Instance{}
	}

	maxIdx := -1
    //第一步: 所有节点累加权重
	for i := 0; i < len(list); i++ {
		w.currentWeight[i] += w.weights[i]
        // 第二步: 选中最大权重节点
		if maxIdx == -1 || w.currentWeight[i] > w.currentWeight[maxIdx] {
			maxIdx = i
		}
	}
    //第三步: 对所选的节点减去总权重
	w.currentWeight[maxIdx] -= w.totalWeight
	return list[maxIdx]
}

```

下面是一个例子:

假设有两个服务器,A权重是5 , B权重是1, 那么total(总权重)为6, 

初始化的时候currentWeight = [0,0]

第一轮加上各自的权重:

[5,1]

那么会选择A, 减去总权重后,当前权重变为:

[-1,1]

第二轮加上各自的权重:

[4,2] 

那么会选择A, 减去总权重后,当前权重变为:

[-2,2]

第三轮加上各自的权重:

[3,3] 

那么会选择A, 减去总权重后,当前权重变为:

[-3,3]

第四轮加上各自的权重:

[2,4]

那么会选择B, 减去总权重后,当前权重变为:

[2,-2]

以此类推,会发现B并不是在第六次中才出现

而是第四次就插入进来了, 变成如下

```go
AAABAA
```

这就更平滑了
