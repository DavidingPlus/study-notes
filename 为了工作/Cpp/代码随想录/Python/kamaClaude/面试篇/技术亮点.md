## 亮点一：守护进程 + 多客户端架构

**设计**：`kama-core` 守护进程持久运行，`kama-tui` / `kama` CLI 作为客户端通过 TCP 连接。客户端断开不中断 Agent 执行，重连后可恢复订阅。

**实现细节**：

* 传输层：`asyncio.start_server` + NDJSON framing，每行一个 JSON-RPC 2.0 消息
* 服务器启动时探测端口，已有守护进程则快速失败，避免双启
* 客户端通过 `event.subscribe`（支持 glob topic）注册感兴趣的事件，服务器仅推送匹配项

**为什么这样设计**：TUI 崩溃或用户关闭终端不会杀死正在执行的 Agent；未来可接入 Web 前端而无需修改核心。

***

## 亮点二：Pydantic v2 Discriminated Union 类型化协议

**设计**：所有 IPC 事件和命令均为 Pydantic v2 模型，通过 `type` 字段的 discriminated union 在反序列化时自动分发到正确类型。

```python
Event = Annotated[
    RunStartedEvent | StepStartedEvent | ToolCallStartedEvent | SubagentStartedEvent | ...,
    Discriminator("type"),
]
```

**收益**：

* 新增事件类型只需加一个 Pydantic 模型 + union 成员，类型系统自动保证处理覆盖
* `WIRE_PROTOCOL.md` 由脚本从模型自动生成，文档与代码永远同步
* mypy strict 模式下，事件字段访问全部有类型推断，无需 `dict.get()` 猜测字段名

***

## 亮点三：Agent 循环与流式重试

**设计**：`AgentLoop` 实现标准的 ReAct 循环（think → tool call → observe → repeat），终止条件为 LLM 不再调用工具或达到步数上限。

**流式重试**：

```plain
网络中断 → 捕获 httpx.RemoteProtocolError / httpx.ReadTimeout
→ 截断已接收的 partial token stream
→ 指数退避（1s / 2s / 4s）重试，最多 3 次
→ 重试时复用同一 message history，不重复计费已完成的步骤
```

**Prompt Caching**：系统 prompt 和工具 schema 标记 `cache_control: {"type": "ephemeral"}`，多步对话中命中缓存可减少 90% 以上的输入 token 计费。

***

## 亮点四：上下文压缩（Context Compaction）

**问题**：长对话的 message history 会超过模型 context window（200k tokens），需要在不丢失关键信息的情况下压缩。

**设计**：

1. 每次 LLM 调用后检查 `context_pct`（已用 token / context window）
2. 超过可配置阈值（默认 80%）时触发压缩
3. 将完整历史作为输入，调用 Claude 生成结构化摘要
4. 用摘要替换历史，保留最新 1–2 轮消息保持上下文连贯
5. 支持用户手动触发（`/compact` 命令），TUI 显示节省的 token 数

***

## 亮点五：工具权限管理系统

**设计**：所有工具调用在执行前经过 `PermissionManager` 检查，策略分四级：

| 策略 | 含义 |
| --- | --- |
| `allow_once` | 本次允许 |
| `always_allow` | 该工具永久允许（持久化） |
| `deny_once` | 本次拒绝 |
| `always_deny` | 该工具永久拒绝（持久化） |

**TUI 集成**：`PermissionSelect` 控件直接挂载在输入框上方，无需弹窗，键盘快捷键（`y/a/n/d`）或方向键 + Enter 确认。权限决策写回守护进程，不阻塞消息循环。

***

## 亮点六：多 Agent 编排与事件桥接

**设计**：`SpawnAgentTool` 将子 Agent 作为普通工具调用暴露给 LLM，父 Agent 在 tool\_use 中传入 description / goal，工具内部启动完整的子 AgentLoop。

**事件桥接**：

```plain
子 AgentLoop → 子 EventBus.publish(event)
                    ↓ bridge 函数（subscribe 回调）
              父 EventBus.publish(event)  ← TUI 接收并渲染
```

子 Agent 的工具调用、token 流、步骤信息全部透传，TUI 用 `┌─/└─` 树形结构区分层级，子 Agent 工具块额外缩进。

**BackgroundTaskRegistry**：支持 `run_background` 模式，子 Agent 异步运行，父 Agent 继续执行其他任务，通过 run\_id 轮询结果。

***

## 亮点七：Skills 机制

**设计**：Skills 是轻量的「行为预设」，用 Markdown front-matter 描述 system prompt 覆盖和工具白名单，无需修改代码即可扩展 Agent 能力。

```markdown
---
name: review
description: 代码审查 agent
system_prompt: 你是代码审查专家...
allowed_tools: [read_file, list_dir, bash]
---
```

**三级查找**（低优先级 → 高优先级）：

1. `src/kama_claude/core/skills/builtin/`（内置）
2. `~/.kama/skills/`（用户全局）
3. `.kama/skills/`（项目本地）

同名 Skill 由高优先级覆盖，用户可在不修改项目代码的情况下替换内置行为。

***

## 亮点八：MCP 客户端

**设计**：实现 Model Context Protocol（MCP）客户端，支持通过 stdio 或 TCP 启动外部工具服务器，工具注册时以 `{server}__{tool}` 命名前缀避免冲突。

**协议实现**：JSON-RPC 2.0 over NDJSON，支持 `tools/list` 发现工具、`tools/call` 执行工具，响应通过 `asyncio.Future` 异步等待，超时自动取消。

***

## 亮点九：Textual TUI 实时渲染

**LLM 流式输出**：`LLMStreamBlock` 在同一 widget 中累积 token，结束后一次性转 Markdown 渲染（`rich.Markdown`），避免每个 token 触发 DOM 重排。

**工具调用块**：`ToolCallBlock` 点击可折叠，展开显示完整 params 和 output，支持 `note_save` 等工具的特殊摘要格式。

**Slash 补全弹窗**：输入 `/` 立即弹出 `SlashCompleteWidget`，实时过滤所有已注册 Skill 和内置命令，无需焦点切换，Tab/Enter 选择后自动填入输入框。
