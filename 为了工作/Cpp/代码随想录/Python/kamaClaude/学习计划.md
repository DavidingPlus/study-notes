## 二、学习时长评估

学习时长取决于目标深度。以一名**有中等 Python 基础、了解异步编程、对 AI Agent 架构有基本认知**的工程师为基准：

| 学习目标 | 方式 | 估算工时 | 按每天 2h 计 | 按每天 4h 计 |
| --- | --- | ---: | ---: | ---: |
| **通读理解**（读懂架构与主流程，能讲清数据流） | 顺序读 src + 跑通 demo | ~18–25 h | 约 2 周 | 约 1 周 |
| **深度精读**（逐模块吃透，读测试，能改 bug、加小功能） | 精读 + 跑测试 + 调试 | ~45–60 h | 约 4–5 周 | 约 2–3 周 |
| **完全复刻**（按阶段自己从零重写一遍，时间成本高，不建议） | 对照设计文档手写实现 | ~90–130 h | 约 9–13 周 | 约 5–7 周 |

> 评估依据：纯代码约 9,200 行。通读按 ~400 行/小时（含查文档）；精读按 ~150 行/小时（含读测试、动手调试）；复刻按 ~80 行/小时（含查资料、踩坑、调通）。异步 IPC、MCP、多代理编排是难点，需额外预留时间。

**推荐目标：深度精读**——既能真正掌握一个生产级本地 Agent 系统的设计，又不会陷入复刻的高时间成本。

## 三、学习计划（4 周 / 深度精读，约 50 小时）

学习顺序**可沿用项目的 S0→S7 阶段演进**，因为每个阶段的代码是在前一阶段基础上迭代而来的，跟着阶段走 = 跟着设计思路走。每个阶段可 `git checkout stage/sN` 切到对应快照，只看当时存在的代码，避免被后期复杂度干扰。

### 前置准备（0.5 天）

* \[ ] 跑通环境：`uv sync`，`uv run pytest tests/unit -v` 全绿
* \[ ] 读 `CLAUDE.md`、`README`、`WIRE_PROTOCOL.md`，建立全局认知
* \[ ] 跑一遍 demo：`uv run kama-core` + 另开终端 `uv run kama ping`

### 第 1 周：协议与骨架（S0–S2，约 12h）

**目标：搞懂双进程架构、IPC 协议、Agent 主循环、TUI 前端如何串起来。**

* \[ ] **S0** `core/bus/`（信封/命令/事件三件套，理解 discriminated union 契约）→ `core/transport/socket_server.py`（NDJSON 读写、handler 分发）→ `core/config.py`（四级优先级）→ `core/app.py`（启动流程）
* \[ ] 对应测试：`test_envelope.py`、`test_socket_server.py`、`test_config_env.py`、`test_ping_roundtrip.py`
* \[ ] **S1** `core/llm/`（Provider 抽象）→ `core/loop.py` + `core/runner.py`（Agent 推理循环）→ `core/trace/`
* \[ ] **S2** `tui/app.py`（主前端）+ `test_s2_dual_process.py`（双进程联调）
* \[ ] **产出**：手画一张"用户输入 → CLI/TUI → socket → core → LLM → 工具 → 回流"的数据流图

### 第 2 周：工具与上下文（S3–S4，约 13h）

**目标：搞懂工具如何注册/调用、上下文如何组装与压缩、会话如何持久化。**

* \[ ] **S3** `core/tools/base.py` + `registry.py` + `invocation.py`（工具协议与重试）→ `core/tools/builtin/*`（逐个读 bash/read\_file/write\_file/list\_dir/task\_\* 等内置工具）
* \[ ] `core/context.py`（system prompt 与上下文组装）→ `core/compact/`（budget + compactor 压缩策略）→ `core/memory/loader.py`
* \[ ] **S4** `core/session/`（store/model/manager 持久化与会话级 IPC）+ `test_s4_session_ipc.py`
* \[ ] 对应测试：`test_tool_registry.py`、`test_invocation.py`、`test_tool_retry.py`、`test_builtin_tools.py`、`test_context.py`、`test_compactor.py`、`test_budget.py`、`test_session_*.py`
* \[ ] **产出**：给项目新增一个简单的内置工具（如 `echo`），跑通端到端——这是检验掌握程度的最佳方式

### 第 3 周：权限与任务（S5–S6，约 10h）

**目标：搞懂工具调用前的权限审批流、任务的建模与生命周期管理。**

* \[ ] **S5** `core/permissions/policy.py`（策略规则）→ `manager.py`（审批流）→ `storage.py` + `errors.py`
* \[ ] 重点理解：权限如何在工具调用链中插入、TUI 如何展示审批请求、`test_s5_permission_flow.py` 的端到端流程
* \[ ] **S6** `core/task/model.py` + `manager.py`，以及 `core/tools/builtin/task_*.py`（任务工具如何复用任务子系统）
* \[ ] 对应测试：`test_permission_policy.py`、`test_permission_manager.py`、`test_task_model.py`、`test_task_manager.py`
* \[ ] **产出**：用文字描述一次"工具触发 → 命中权限策略 → 用户审批 → 执行/拒绝"的完整时序

### 第 4 周：高级编排（S7，约 13h）

**目标：搞懂子代理、技能、MCP 这三大扩展机制，理解多代理编排。这是项目最复杂、最有价值的部分。**

* \[ ] **子代理** `core/subagent/registry.py` + `tool.py` + `core/agents/loader.py`（agent profile）→ `test_spawn_agent_tool.py`、`test_agent_profile_loader.py`
* \[ ] **技能** `core/skills/loader.py` + `.kama/skills/` 下的实际技能文件（目录式技能、YAML 块标量）→ `test_skill_loader.py`
* \[ ] **MCP** `core/mcp/client.py` + `server.py` + `tool.py`（外部工具接入协议）→ `test_mcp_tool.py`
* \[ ] 扩展思考（extended thinking）在对话历史中的处理（见 commit `68922eb`）
* \[ ] **产出**：写一个自定义技能放进 `.kama/skills/`，让 agent 调用成功；画一张多代理编排的协作图

### 收尾（约 2h）

* \[ ] 通读 `scripts/gen_protocol_doc.py`，理解协议文档如何从模型自动生成
* \[ ] 复盘：对照 S0→S7 的增长曲线，总结"一个 Agent 系统是如何分层生长出来的"
* \[ ] 尝试回答：如果要做 S8，你会加什么？怎么加？

## 四、学习方法建议

1. \*\*跟着阶段走，不要一头扎进 \*\*`stage/s7`。先 `git checkout stage/s0`，代码只有 459 行，一眼能看完，建立信心后逐阶段叠加。
2. **代码与测试对照读**。本项目测试注释要求写明"功能"与"设计"两行，测试本身就是最好的行为说明书。
3. **每个阶段都动手**。读懂不等于会写，每周的"产出"任务是检验标准。
4. **难点重点投入**：异步 IPC（transport）、上下文压缩（compact）、多代理编排（subagent）是三个最值得花时间的硬骨头。
5. **善用项目本身**：`uv run kama-tui` 跑起来，边用边对照代码看事件如何流动。
