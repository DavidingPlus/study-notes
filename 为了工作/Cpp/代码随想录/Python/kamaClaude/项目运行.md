# 本地开发环境搭建：从 clone 到第一次跑通

> **<font style="color:#333333;">建议购买一台云服务器，腾讯云或者阿里云，用来部署自己的项目 非常方便，无论是做本项目还是做其他项目，无论是自己练习，还是项目上线，都需要一台有公网Ip的独立服务器。 自己电脑安装虚拟机，不仅麻烦，经常出莫名其妙的问题。</font>**

> * [腾讯云活动期间服务器购买](https://curl.qcloud.com/EiaMXllu)

这篇不是讲 KamaClaude 的内部设计，而是先把开发环境跑起来。

如果环境没搭好，后面的 S0、S1、S2 看起来都会像"代码有问题"：命令找不到、Python 版本不对、daemon 连不上、LLM API key 没读到。我们先把这些基础问题一次性处理掉。

最终目标是做到三件事：

```bash
uv run kama --version    # 能看到版本
uv run kama ping         # 能连上 kama-core
uv run kama run --goal "用一句话介绍这个项目"  # 能完成一次真实 agent run
```

前两个只验证本地项目和 daemon；第三个会调用 LLM，需要 `.env` 里配置好 Anthropic API。

***

## 准备系统环境

KamaClaude 当前要求：

| 依赖 | 要求 |
| --- | --- |
| Python | 3.12.x |
| uv | 0.4 或更高 |
| Git | 能 clone 仓库 |

Python 不需要你手动装。项目使用 `uv` 管理虚拟环境和 Python 版本，后面 `uv sync` 会按 `pyproject.toml` 的要求准备 Python 3.12。

先确认有 Git：

```bash
git --version
```

如果这条命令不存在，需要先安装 Git。

***

## 下载项目代码

从你的仓库地址 clone：（**欢迎star，fork**）

```bash
git clone https://github.com/youngyangyang04/KamaClaude.git
```

当前教程仓库里，真正的 Python 项目在 `KamaClaude/` 目录下，所以进入代码目录：

```bash
cd KamaClaude
```

后面的命令都在 `KamaClaude/` 目录里执行。你可以用下面的命令确认位置对不对：

```bash
ls
```

应该能看到这些文件：

```latex
pyproject.toml
README.md
RUNBOOK.md
src/
tests/
.env.example
```

如果没有看到 `pyproject.toml`，说明你还没进入真正的项目目录。

***

## 安装 uv

项目用 `uv` 做三件事：

* 安装依赖
* 创建虚拟环境
* 运行项目命令，例如 `uv run kama-core`

如果你还没有安装 uv，执行：

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

安装完成后，重开一个终端，或者让当前 shell 重新加载 PATH。然后验证：

```bash
uv --version
```

如果提示 `command not found: uv`，通常是 PATH 还没刷新。可以先重开终端；如果还不行，检查安装脚本最后输出的 PATH 提示。

## 同步依赖

在 `KamaClaude/` 目录执行：

```bash
uv sync
```

这一步会读取 `pyproject.toml`：

```toml
[project]
requires-python = ">=3.12,<3.13"
dependencies = [
    "pydantic>=2.0",
    "python-dotenv>=1.0",
    "anthropic>=0.25",
    "textual>=0.75",
]

[project.scripts]
kama = "kama_claude.cli.main:main"
kama-core = "kama_claude.core.app:run"
kama-tui = "kama_claude.tui.__main__:main"
```

同步完成后，先验证命令入口能不能跑：

```bash
uv run kama --version
```

应该输出类似：

```latex
0.0.1
```

这一步不需要启动 daemon，也不需要 API key。它只说明：依赖装好了，包能 import，命令入口生效了。

## 配置 `.env`

项目提供了 `.env.example`，先复制一份：

```bash
cp .env.example .env
```

然后编辑 `.env`：

```bash
vim .env
```

或者用你常用的编辑器打开。

一个本地开发常用配置如下：

```plain
# Core Daemon
KAMA_HOST=127.0.0.1
KAMA_PORT=7437

# Logging
KAMA_LOG_LEVEL=INFO
KAMA_LOG_FILE=~/.kama/logs/core.log
KAMA_LOG_FORMAT=text

# 模型相关配置
ANTHROPIC_API_KEY=sk-ant-你的真实-key  # api key
KAMA_LLM_DEFAULT_MODEL=claude-sonnet-4-6  # 默认的 model
KAMA_MAX_STEPS=20 # 最大循环次数
```

> ⚠️ `.env` 里会放真实密钥，不要提交到 Git。文档里只写字段名和占位值，不要把真实 `ANTHROPIC_API_KEY` 贴出来。

### <font style="color:#DF2A3F;">使用国产模型替代 Claude 模型（便宜）</font>

以 deepseek 为例，修改为 .env 文件

```python
# deepseek api key
ANTHROPIC_API_KEY=sk-xxxxxxx

# deepseek 兼容 Anthropic 风格的接口
ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic

# deepseek 的模型
KAMA_LLM_DEFAULT_MODEL=deepseek-v4-flash
```

### <font style="color:#DF2A3F;">使用 Claude opus 4.8、opus 5、fable5 模型（能力确实强）</font>

如果用上opus4.8，你会发现，同样的agent，用上更强的模型，确实不一样，强大很多。

如果想使用 claude opus 4.8 ，opus 5模型，原汁原味还原 claude code 的能力。但是不会魔法或者没有 claude 的账号，可以考虑找一些性价比高且稳定的中转站。

如果没有自己的中转站选择，可以考虑使用 <https://apidock.ai> ，测试下来总体还算稳定。

参考配置文件：

```python
# apidock 控制台申请的 API Key
ANTHROPIC_API_KEY=sk-xxxxxxx

# apidock 提供的兼容 Anthropic 风格的接口
ANTHROPIC_BASE_URL=https://apidock.ai

# 模型名称
KAMA_LLM_DEFAULT_MODEL=claude-opus-4-8 
# 如果用opus 5 ，就换成 claude-opus-5
```

## 启动 daemon

打开第一个终端，进入 `KamaClaude/`，启动 Core：

```bash
uv run kama-core
```

正常情况下，它会一直运行，不会立刻退出。默认监听：

```latex
127.0.0.1:7437
```

如果你配置了日志文件，可以另开一个终端看日志：

```bash
tail -f ~/.kama/logs/core.log
```

如果启动时报：

```latex
Address already in use
```

说明端口已经被占用。可能是另一个 `kama-core` 已经在运行。可以先检查：

```bash
pgrep -f kama-core
```

如果确认是旧进程，可以停止：

```bash
kill $(pgrep -f kama-core)
```

或者临时换端口：

```bash
KAMA_PORT=8000 uv run kama-core
```

换端口时，客户端也要用同一个 `KAMA_PORT=8000`。

***

## 用 ping 判断 daemon 是否成功

保持第一个终端里的 `kama-core` 运行。打开第二个终端，同样进入 `KamaClaude/`，执行：

```bash
uv run kama ping
```

成功时会看到类似：

```latex
pong server=0.0.1 uptime=12ms latency=2ms
```

这说明三件事都通了：

* CLI 读到了配置里的 host/port。
* CLI 成功连接到 daemon。
* daemon 收到 `core.ping` 请求并返回了响应。

如果看到：

```latex
error: core not running (127.0.0.1:7437)
```

通常是 daemon 没启动，或者 CLI 和 daemon 使用的端口不一致。检查：

```bash
grep KAMA_PORT .env
```

再确认启动 daemon 的终端是不是同一个端口。

## 跑一次真实 agent run

`ping` 只验证本地 IPC，不会调用 LLM。要验证 LLM 配置和工具链，跑一次最小任务：

```bash
uv run kama run --goal "用一句话介绍这个项目"
```

成功时，你应该能看到类似这样的过程：

```latex
[run] 20260527-...
[step 1] planning...
KamaClaude 是一个本地运行的 AI Agent 系统...
[run] success  1 steps  ...
```

同时 session 或 run 目录下会出现事件文件。根据当前阶段实现，运行数据通常会落在：

```latex
~/.kama/sessions/<session_id>/runs/<run_id>/events.jsonl
```

你可以找最近的事件文件：

```bash
find ~/.kama/sessions -name events.jsonl -print | tail -5
```

如果 run 报 `ANTHROPIC_API_KEY` 相关错误，说明 `.env` 没配置或没有被当前命令读到。确认：

```bash
grep '^ANTHROPIC_API_KEY=' .env
```

只确认这一行存在，不要把值贴到聊天或 issue 里。

***

## 打开 TUI

daemon 跑着时，可以启动终端 UI：

```bash
uv run kama-tui
```

TUI 成功连接后，应该能看到连接状态和输入框。你可以在输入框里发一句：

```latex
用一句话介绍这个项目
```

如果触发了工具权限审批，TUI 会出现审批卡片；如果只是普通回答，会看到 token 流式输出和 usage 信息。

如果 TUI 一直连不上，先退回 `uv run kama ping`。ping 不通时，TUI 也一定不通。

***

## 成功标准

本地开发环境算搭建成功，需要满足这几条：

```bash
uv run kama --version
```

能输出版本。

```bash
uv run kama-core
```

能启动并持续运行。

```bash
uv run kama ping
```

能返回 `pong`。

```bash
uv run kama run --goal "用一句话介绍这个项目"
```

能完成一次 LLM run，终端看到结果，`~/.kama/sessions/` 下能找到 `events.jsonl`。
