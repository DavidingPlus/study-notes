# 5. Pytest 中的case前后置处理与数据驱动

在自动化测试中，前后置处理（setup 和 teardown）是非常重要的部分，它帮助我们在测试执行前准备环境，并在测试完成后进行清理。

## 1. UnitTest 中的前后置处理
在经典的 UnitTest 框架中，前后置处理通过 setup 和 teardown 实现。通过定义 setup_class 或 teardown_class，我们可以确保某些操作在所有测试用例执行前后只执行一次。

```python
def setup_method(self):
    print("前置处理，每个测试方法执行前都会运行")

def teardown_method(self):
    print("后置处理，每个测试方法执行后都会运行")

```

+ setup_method：在每个测试用例执行之前运行。
+ teardown_method：在每个测试用例执行之后运行。

## 2. Pytest 中的前后置处理
Pytest 提供了一种更灵活的方式来实现前后置处理，即通过 pytest.fixture 装饰器来实现。yield 关键字在 Pytest 中作为前后置处理的分隔点，yield 之前的代码在测试前执行，yield 之后的代码在测试后执行。

```python
import pytest

@pytest.fixture
def setup_teardown():
    print("前置处理")
    yield
    print("后置处理")

```

在每个测试用例执行时，setup_teardown 中的前置处理会自动运行，在测试完成后，后置处理自动触发。

## 3. conftest.py 文件中的前后置处理
Pytest 提供了第三种前后置处理方式：在 conftest.py 文件中定义全局的前后置处理逻辑。conftest.py 是一个特殊文件，可以被所有测试用例共享，适合用于初始化全局状态。

```python
# conftest.py
import pytest

@pytest.fixture(scope="session", autouse=True)
def global_setup():
    print("全局前置处理")
    yield
    print("全局后置处理")

```

+ scope 参数可以定义前后置操作的作用范围：function、class、module、package、session。
+ autouse=True 表示该 fixture 会自动应用于所有测试用例。

## 4. Pytest 作用域管理
在 pytest.fixture 中，通过 scope 参数可以灵活管理前后置处理的执行频率：

+ function ：每个测试函数执行前后运行一次。
+ class ：在测试类的作用域内，前后置处理仅执行一次。
+ module ：跨文件的情况下，每个模块只执行一次前后置处理。
+ session ：测试会话期间，全局的前后置处理仅执行一次。

```python
@pytest.fixture(scope="class")
def setup_class():
    print("类的前置处理")
    yield
    print("类的后置处理")

```

这种灵活性让我们可以根据具体需求，控制前后置处理的作用范围，从而提高测试的效率与可维护性。

## 5. 示例解析
以下是一个简单的例子，通过 pytest.fixture 实现前后置处理：

```python
import pytest

@pytest.fixture
def setup_teardown():
    print("执行前")
    yield
    print("执行后")

def test_case_1(setup_teardown):
    print("测试用例 1 执行")

def test_case_2(setup_teardown):
    print("测试用例 2 执行")

```

在每个测试用例执行前，Pytest 会自动执行 setup_teardown 中的前置处理部分；在测试用例执行后，后置处理会自动触发。

## 6. 参数化处理
Pytest 支持通过 pytest.mark.parametrize 进行参数化测试，可以一次性测试多个输入组合，减少重复编写代码的情况。

```python
import pytest

@pytest.mark.parametrize("input, expected", [
    (1, 2),
    (2, 4),
    (3, 6)
])
def test_multiply(input, expected):
    assert input * 2 == expected

```

parametrize 提供了一种简洁的方式定义测试输入和期望输出，通过一次性传递多个值，减少冗余代码。

## 7. 结合 conftest.py 的多文件支持
conftest.py 文件可以根据项目结构放置在不同层级的目录中，从而控制前后置处理的作用范围。例如：

+ 在根目录下的 conftest.py 可能用于全局的前后置处理。
+ 在子模块中的 conftest.py 可以针对该模块内的测试用例进行特定处理。

```python
# 项目根目录 conftest.py
@pytest.fixture(scope="session")
def global_setup():
    print("全局前置处理")

# 子模块 test_case 目录下的 conftest.py
@pytest.fixture(scope="function")
def module_setup():
    print("模块前置处理")

```

## 8. Pytest 与 YAML 文件结合实现数据驱动
在接口自动化测试中,将测试数据与测试逻辑分离是一种良好的实践。Pytest 结合 YAML 文件可以很好地实现这一点,使得我们的测试更加灵活和易于维护。

### 8.1 准备工作
首先,我们需要安装必要的库:

```bash
pip install pytest pyyaml

```

然后,创建一个用于读取 YAML 文件的工具类:

```python
# utils/YamlUtil.py
import yaml

class YamlReader:
    def __init__(self, yaml_file):
        self.yaml_file = yaml_file
  
    def data(self):
        with open(self.yaml_file, 'r', encoding='utf-8') as f:
            return yaml.safe_load(f)

```

### 8.2 编写测试用例
假设我们有一个登录接口需要测试,我们可以这样编写测试用例:

```python
# test_login.py
from utils.YamlUtil import YamlReader
from utils.RequestsUtil import RequestsUtil

def test_login():
    # 读取 YAML 文件
    case_info = YamlReader('../testcases/login/login.yaml').data()
  
    # 提取接口信息
    url = str(case_info[0]['request']['url'])
    method = case_info[0]['request']['method']
    headers = case_info[0]['request']['headers']
    data = case_info[0]['request']['data']
  
    # 发送请求
    req = RequestsUtil()
    res = req.send_request(url=url, data=data, headers=headers, method=method)
  
    # 断言
    assert res.json()['message'] == '登录成功'

```

### 8.3 YAML 文件结构
对应的 YAML 文件 (login.yaml) 可能如下所示:

```yaml
-
  name: 登录测试
  request:
    url: /api/login
    method: POST
    headers:
      Content-Type: application/json
    data:
      username: testuser
      password: password123
  validate:
    - eq: [status_code, 200]
    - eq: [$.message, "登录成功"]

```

### 8.4 优化测试框架
为了进一步简化测试用例的编写,我们可以在 APIUtil.py 中定义一个通用方法:

```python
# utils/APIUtil.py
from utils.YamlUtil import YamlReader
from utils.RequestsUtil import RequestsUtil

class APIUtil:
    @staticmethod
    def get_case_info(yaml_file):
        case_info = YamlReader(yaml_file).data()
        url = str(case_info[0]['request']['url'])
        method = case_info[0]['request']['method']
        headers = case_info[0]['request']['headers']
        data = case_info[0]['request']['data']
        return url, method, headers, data

    @staticmethod
    def send_request(yaml_file):
        url, method, headers, data = APIUtil.get_case_info(yaml_file)
        req = RequestsUtil()
        return req.send_request(url=url, data=data, headers=headers, method=method)

```

现在,我们的测试用例可以更加简洁:

```python
# test_login.py
from utils.APIUtil import APIUtil

def test_login():
    res = APIUtil.send_request('../testcases/login/login.yaml')
    assert res.json()['message'] == '登录成功'

```

### 8.5 数据驱动测试
利用 Pytest 的参数化功能,我们可以轻松实现数据驱动测试:

```python
import pytest
from utils.APIUtil import APIUtil

@pytest.mark.parametrize("yaml_file", [
    '../testcases/login/login_success.yaml',
    '../testcases/login/login_fail_wrong_password.yaml',
    '../testcases/login/login_fail_invalid_user.yaml'
])
def test_login(yaml_file):
    res = APIUtil.send_request(yaml_file)
    assert res.status_code == 200

```
